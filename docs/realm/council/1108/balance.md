# 밸런스 자리 (11-08) — 값은 그대로, 살림은 열 배

> 근거는 전부 헤드리스 시뮬 출력이다. 날짜 2026-11-08 · params 는 이날의 `src/tune/params.ts`.

## 0. 먼저 — `npm run balance` 는 이 판을 못 잰다

- `npm run balance` = `tools/balance-sim.ts` = **옛 활터(스테이지 64개) 시뮬**이다. 돌렸고 정상 종료(`stage 1-1 … clear 100%`)했지만 나라 판의 값·살림은 하나도 안 잰다.
- 나라 판의 시뮬은 `tools/realm-sim.ts`(이김·짐·싸움만 · 살림 곡선 없음). 그래서 이번에 **임시 측정 스크립트**(레포 밖 · 아래 §5 에 고리만)를 짜서 계절마다 플레이어 자리 봇의 살림을 찍었다.
- 플레이어 자리 봇 = `decide(r, as, 'planner')`(`src/realm/ai.ts:770`). 징병·개척·제사·일터(`ai.ts:610`)·곳간 열기(`ai.ts:624`)는 하지만 **상단(사기·팔기·주문)·터 닦기·원정은 안 한다** → 봇의 곡식 창고는 형보다 크게 쌓인다(형 #15 s100 곡식 4660 · 봇 s99 32834). 벌이(가을걷이·특산)는 행동과 덜 엮여 형 기록과 잘 맞는다(집 형 31044 · 봇 27750).
- `realm-sim` 으로 본 쉬움 판: 영남 이서 planner 8판×100계절 — 이김 0% · 짐 0% · 끝땅 22.75 · 싸움/판 5.88. **봇은 싸워 이기지 않고 개척으로 큰다.** 이김률로 난이도를 말하지 말고 아래 살림 곡선을 볼 것.

**결론: 살림은 판 안에서 10~30배 커지는데, 아래 값 대부분은 판 내내 상수다.**

### 2-3. 읽은 것

1. **상단의 주문이 형 말 그대로다.** 초반엔 나무 120 이 벌이 15계절치(상단은 1.3계절마다 오는데 열한 번을 기다린다), 후반엔 창고가 스물두 번을 덮는다. 값이 **곡식 어치로 고정**이라 벌이가 작은 물건일수록 초반에 벽이 된다.
2. **갚음도 같이 줄어든다.** 장수 한 명은 s8 엔 장수진의 1/2, s99 엔 1/10. 「소문」 갚음은 봇 판에서 **s16 부터 비어**(모르는 나라 0) 그 뒤 주문은 늘 장수 하나다.
3. **곱으로 듣는 물건 + 고정 값 = 후반 공짜.** 씨앗(가을걷이 %)·큰 북(모든 군대)·비단(아는 나라마다)은 갚음이 저절로 크는데 값이 그대로다. 씨앗은 s8 에 사면 손해(×0.45), s99 엔 15배 남는다 — **곡선이 거꾸로다.**
4. 고을마다 드는 값(일터·터 닦기·목책)은 고을 하나의 벌이와 견줘야 한다. 고을 하나 가을걷이는 s8 211 → s99 611(×2.9)뿐이라 이쪽은 덜 급하다.
5. **값만으로는 압도를 못 막는다 (측정).** s40 에 쉬움의 살림 덤을 끄고(`easyOurs`·`easyIncome` → 1) 돌려 봤다 (이서 8판):

| s99 | 쉬움 그대로 | s40 부터 살림 덤 끔 | 살림+싸움 덤 끔 (`easyPower` 1 · `easyMorale` 0) | 보통 (tier1) |
|---|---|---|---|---|
| 우리 고을 | 23 | 22 | 23 | 20 |
| 우리 가을걷이 | 14059 | 9435 | 10262 | 7601 |
| 우리 군사 | 11245 | 11132 | 11292 | 9909 |
| 가장 센 남 군사 | 1448 | 3715 | 3736 | 4020 |
| **우리/남 군사** | **×7.8** | ×3.0 | ×3.0 | ×2.5 |

→ 쉬움 덤을 끄면 남은 2.6배 커지지만 우리는 그대로 크다(눈덩이는 개척·집에서 온다). **값 늘리기는 「쓸 데가 있다」를 고치고, 「압도」는 남 쪽 장치가 함께 있어야 한다** (design.md 몫). 다만 쉬움 덤을 판 뒤로 갈수록 거두는 것(§3-4)은 숫자가 뒷받침한다.

## 3. 제안 — 나라 크기 눈금 하나로

### 3-1. 눈금

```
realmScale(r, f) = clamp( (hhOf(r, f) / scaleRefHH) ^ scaleExp , 1 , scaleMax )    // economy.ts 에 하나 · 판을 읽기만
```

| 새 params (`P.realm`) | 값 | 까닭 |
|---|---|---|
| `scaleRefHH` | 1800 | 첫 해 집(1426~1907) 언저리 — 초반은 지금 값 그대로(눈금 1) |
| `scaleExp` | 0.85 | 1 밑: 커질수록 **조금은** 넉넉해야 자라는 맛이 산다 |
| `scaleMax` | 12 | 큰 판(삼한) 끝에서 끝없이 오르지 않게 |

- 집으로 잰다: 같은 결의 선례가 이미 있다(곳간 열기 `economy.ts:742` · 봄 제사 `economy.ts:931`). 가을걷이로 재면 논을 지을수록 값이 올라 투자를 벌한다. 난세 단계 덤(`tierMul`)이 안 섞여 쉬움/어려움의 차이도 그대로 남는다.
- 이서 판의 눈금: s8 **1.0** · s40 **3.39** · s52 5.06 · s80 8.16 · s99 **10.2** (하슬라 s99 6.74).
- 효과: 값 C × 눈금이면 가을걷이 대비 28.4% → 15.3%(s40) → **8.7%(s99)**. 지금은 28.4% → 0.85% (33배 떨어짐) · 바꾸면 3.3배 떨어짐.
- 결정론(A1): 판 상태만 읽는다. `Math.pow` 는 이미 `merchant.ts:66` · `works.ts:56` 에서 쓴다. 값에 쓰기 전 `Math.round`. 주문·상단 물건은 **만들 때 값이 박혀 저장**되므로(`Wish.goods` · `Offer.price`) 옛 저장 이주가 필요 없다.

### 3-2. 상단의 주문 (1순위) — 곡식 어치 대신 「벌이 몇 계절치」

```
y_g     = Σ 우리 고을 nodeYield(r, n, 'summer')[g]      // makeWish 가 이미 이 고리를 돈다 (merchant.ts:255)
want[g] = max(wishMin, round5( wishSeasons × y_g ))      // 위 끝: wishWorth × realmScale / worthOf(g)
```

| 새 params | 값 |
|---|---|
| `wishSeasons` | 2.5 (상단이 두 번 오가는 틈 ≈ 2.7계절) |
| `wishMin` | 5 (지금 바닥과 같다) |
| `wishWorth` | 위 끝으로만 남긴다 (60 × 눈금) |

| 이서 tier0 | 지금 철 · 나무 | 바꾸면 철 · 나무 | 모으는 계절 지금 → 바꾸면 |
|---|---|---|---|
| s8 | 30 · 120 | **15 · 20** | 5.0 · 15 → 2.5 · 2.5 |
| s40 | 30 · 120 | 25 · 100 | 3.3 · 3.0 → 2.5 · 2.5 |
| s99 | 30 · 120 | **155 · 255** | 0.49 · 1.2 → 2.5 · 2.5 |

초반은 쉬워지고 후반은 다섯 배 무거워진다 — 형의 두 마디(초반 까다로움 · 후반 압도)를 한 식으로 고친다. (창고가 넘치면 여전히 바로 낸다. 창고 몫을 더하는 `wishStockShare` 는 0 으로 두고 형 판을 본 뒤에.)

**갚음도 같은 눈금으로.** 낸 물건의 곡식 어치는 s8 ≈ 40 → s99 ≈ 437 (철 155×2 + 나무 255×0.5). 갚음이 그 `wishRewardMul`(1.5) 배는 돼야 할 만하다. 무엇으로 갚을지는 design 자리가 고르되, 숫자 조건은:
- 장수 풀(26명)이 능력치합 26~36 으로 고르게 낮아(값 104~144) 「더 센 장수」만으로는 폭이 1.4배뿐이다 → 장수 + 눈금에 비례한 덤이 필요하다.
- 「소문」은 s16 부터 비므로, 비었을 때 갈아 끼울 갚음이 있어야 주문이 「늘 장수 하나」로 굳지 않는다.

| — | 일터 · 터 닦기 · 목책 | **보류.** 고을마다의 값이고 고을 벌이는 ×2.9 뿐 (§2-3 ④). 늘린다면 그 고을 집 기준 `(n.hh / 1000)^0.5` | — |
| — | 징병 · 무장 · 곳간 열기 · 봄 제사 · 사건 곡식 · 새 마을 | 이미 큼 (§2-2) — 건드리지 않음 | — |

### 3-4. 쉬움 덤을 판 뒤로 갈수록 거둔다

```
easyOurs 의 실효   = 1 + (easyOurs − 1) / realmScale(플레이어)       // tier.ts:39 tierMul 이 r 을 받게
easyIncome 의 실효 = 1 − (1 − easyIncome) / realmScale(플레이어)
```

이서 s40(눈금 3.39) 우리 가을걷이 덤 1.4 → 1.12 · s99 → 1.04. 초반(눈금 1)은 지금 쉬움 그대로. §2-3 ⑤ 실험(s40 에 한꺼번에 끔)에서 남의 군사 1448 → 3715(×2.6) · 우리 가을걷이 −33% · 우리 고을 23 → 22. 싸움 덤(`easyPower`)은 같이 꺼도 결과가 거의 같다(우리/남 ×3.0) → **살림 덤만 거두면 된다.** (단계적으로 거두는 식 그 자체는 아직 안 돌렸다 — 넣은 뒤 같은 측정으로 확인.)

## 5. 다시 재는 법 · 한계

- 측정 고리 (레포 밖 임시 스크립트): `startRegion(region, 1000+g, as)` → `applyTier(r, 0)` → 턴마다 `advance(r, [...decide(r, as, 'planner'), ...aiOrders(r)])` → 계절 끝(`perSeason` 턴마다)에 `hhOf`·`menOf`·`stockOf`·`nodeYield(…, 'summer')` 합·`harvest` 줄·`foundCost`·`callPrice`·가장 센 남의 `menOf` 를 찍는다. 이서 8판×100계절이 10초. 쉬움 덤 끄기 실험은 s40 첫 턴에 `P.realm.easyOurs = 1` 등을 바꿔 끼웠다 (판마다 처음 값으로 되돌림). **`tools/realm-econ.ts` 로 들여 나라 판의 `npm run balance` 짝으로 두기를 권한다** (이번 자리는 읽기만이라 안 넣었다).
- 봇은 상단을 안 쓰고 싸움을 적게 한다(싸움/판 5.88). 창고 곡식 곡선은 형보다 부풀었다 — 그래서 비율 판정은 **벌이**(가을걷이·특산)로 했다.
- 바꾼 뒤 확인: `npm test` (`tests/realm/merchant.test.ts` 가 상단 값·주문을 본다 · `ambush-rite`·`asks-field` 도 이 상수를 읽는다) · 같은 측정으로 주문 모으는 계절이 s8/s40/s99 모두 2~3 인지 · 형 폰 기록이 오면 형 판의 곡식·철로 §2 표를 다시.
