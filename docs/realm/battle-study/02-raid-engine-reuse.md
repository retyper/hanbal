# 02 · 열전(raid) 엔진에서 무엇을 그대로 쓸 수 있나 (2026-11-25 · 조사 일꾼)

> 줄 번호는 모두 `git show HEAD:<파일>` 기준. [확인] 코드에서 직접 봄(파일:줄) · [잼] 직접 돌려 잼 · [옮김] 문서·주석에서 옮김 · [의견] 내 판단 · 모르면 「못 봄」.

## 맨 위 다섯 줄
1. 열전 엔진은 **「장수 한 명 + 몰려오는 적 + 장수 곁 건물」을 전제로 박은 한 덩어리**다. `haebi.ts` 2168줄 한 파일에 `s.x`·`s.y`(장수 자리) 421번, `s.enemies` 81번 [확인]. 적 개체를 편만 바꿔 쓰는 길은 **없다** — 적은 늘 장수를 향해 걷고, 피해는 `hurt(s,…)` 하나로 장수만 맞는다.
2. 그대로 살릴 만한 것은 **땅·길막기·건물 한 개체·카메라·그림 층·입력 기록 틀**이다. 판의 한 걸음(1/120초) · 씨앗+입력 기록 · 규칙 태그(`HaebiOpts`)라는 **짜임새**도 그대로 배운다 [확인].
3. 건물(망루·목책·포차·봉수대·우물…)은 `build.ts` 176줄에 **순수한 자료+계산**으로 깔끔히 갈려 있어 옮기기 쉽다. 다만 세기가 「장수의 카드 단계(`s.ranks`)」와 「지금 잡졸 체력(`mobHp`)」에 묶여 있고, 적이 건물을 **노리는 것은 id 3의 배수 한정 어그로**뿐이다 (공성이 아니다).
4. **가장 큰 위험은 속도다.** 같은 봇으로 20분 판을 돌리니 규칙을 다 켠 숲 판이 **375초(걸음당 2.6ms, 적 상한 230에 붙음)**, 옛 판 규칙만으론 38초 [잼]. 「맡기기·AI 끼리 싸움」을 이 엔진 그대로 돌리면 안 된다 — 적이 서로 상대 목록을 훑는 구조(O(N²))라 군세 수십×수십이 되면 더 나빠진다.
5. 결론 [의견]: **열전 sim 을 편 가르게 개조하지 말고**, 본편 전투용 새 sim(`src/field/` 같은 곳)을 짓되 **열전에서 「땅(wide·props·solids) · 건물 자료 · 카메라 · 렌더 층 · 기록 틀」을 복사해 간다.** 개조 비용(아주 큼)이 새로 짓는 비용(큼)보다 크다.

## 3. 「우리 편 병사」가 지금 있나 — 없다 (가장 중요)

[확인] 아군 무리·소환물·동료는 **없다.** 「아군」에 가장 가까운 것이 **설치물**(건물)뿐이고, 건물은 움직이지 않는다. 「편」 필드도 어디에도 없다 (`team`·`side`·`owner` 없음 — `Mob`·`Missile` 정의 201·206).

적 개체를 편만 바꿔 쓰려면 아래 **박힌 곳**을 모두 풀어야 한다 [확인]:

## 4. 건물을 유닛으로

[확인] `build.ts` 176줄은 **판 상태를 모르는 순수 계산**(체력·단계·자리·밀기·혼줄 선분 거리) — 옮기기 좋다. 판 쪽 한 걸음은 haebi.ts 1632-1802.

| 건물 | 체력 | 동작 | 장수/카드에 묶인 곳 |
|---|---|---|---|
| 망루 tower | 260+90/단계 × 위협배수 | `range 380` 안 `nearest` 에 `shoot('tower')` 1발, 1.3초마다 (1794-1798) | 피해 = `mobHp(s) × share(단계)`(1675) · 단계 = `s.ranks.tower` · 장전 `reloadIv` |
| 목책 fence | 220+80/단계 | 막기. 닿은 잡졸이 멈춰서 **문다**(1949-1950 `bite`) | 단계 = `s.ranks.fence` |
| 항아리 jar | 무적(75-WALL 판은 체력) | 둘레에서 죽은 적의 기세 ×배수 (755) | 기세(`xp`) 개념 = 열전 레벨업 |
| 장승 totem | 있음 | 둘 사이 **혼줄**로 지나가는 적을 베고 느리게 (1755-1765) | 피해 = `mobHp × lineShare` |
| 솟대 sotdae | 무적 | 둘레 적 감속 (1697-1702) | 단계 |
| 봉수대 beacon | 무적 | 가장 뭉친 곳에 `signal` 화살비, 금빛 표식 뒤 (1716-1724) | `denseSpot` O(N²) · 단계 |
| 포차 catapult | 있음 | `minRange~range` 안 뭉친 곳으로 `lob` 바위 (1726-1735) | 단계 |
| 우물 well | 무적 | **장수** 체력을 채움 (1767-1777) | 장수 전용 |

- **재건**: 체력 0 → 잔해 → `rebuildOf` 초 뒤 같은 자리에 같은 체력으로 다시 섬 (1786-1787) — 「재건」은 이미 있다.
- **밀기**: 장수 몸이 겹치면 건물이 **밀려남**(1661-1673 `heroPush`), 거대 보스도 밀침(1999-2004). 적은 못 밂.
- **적이 건물을 노리는 법**: 어그로 한 가지 — 붙어 싸우는 잡졸 중 `id % aggroEvery === 0`(망루 3, 장승 2)이 `aggroR` 안의 건물로 끌려가 침 (1684-1695, build.ts:72-88). 나머지는 장수만 향함. 즉 **공성/수성이 아니라 「건물이 장수 곁 방패」**다.
- **조준**: 망루=가장 가까운 적, 봉수대=뭉침 가운데, 포차=사거리 안 뭉침. 모두 `s.enemies` 대상. 사격 규칙은 「건물 → 상대 편 개체」로 일반화하면 거의 그대로 쓸 수 있다.
- [의견] 본편 「목책·망루·진영·해자」: 목책/망루/포차/봉수대는 **조금 고침**(대상 편, 체력/피해를 병사 수학으로, 조준 목록). 해자·개울·수상전은 열전에 없는 **지형 효과** — 새로. 56-C 진짜 목책(`palisade.ts`, 마디 체력·문·막힘 계산)이 목책/성벽에 더 맞고 이미 「부수면 지름길」이 구현됨(`wallMove`·`damagePiece`·`heroBash`).

## 11. 맨 끝

### 바로 고칠 것 (이 조사로 보인 것 · 지금 코드)
1. `denseSpot`(haebi.ts:1704-1713)는 적 수의 제곱으로 돈다. 봉수대·포차가 있는 판이 느린 첫째 후보 — 본편에 옮기기 전에 격자나 교대 갱신으로 바꿔 둘 것(열전 판 걸음당 2.6ms 도 이득).
2. sim 에 `Math.sin/cos/atan2` 79곳 — 본편 전투 sim 에는 BATTLE-LIVE 가 말한 정수 격자로 가야 한다(열전은 지금 건드리지 않음).
3. `viewBounds`·`barrageSource`(haebi.ts:277)처럼 **화면이 sim 에 넣는 입력**은 본편 전투 sim 에는 넣지 말 것(AI 끼리 싸움이 못 돈다).
4. `wide.ts` 의 정사각 3×3 `WORLD` 상수와 `huntSpot` 같은 열전 소환 함수는 본편에서 안 쓰므로 새 sim 쪽으로 **복사**해 가고 열전 것은 그대로 둘 것(옛 기록 불변).

### 못 본 것
