# SNIPE — 저격 상세

> SYSTEMS §6 이 "무엇을 하나"라면 이 문서는 **활 sim 위에서 어떻게 돌아가나**다.
> 신궁의 코드와 새 게임이 맞닿는 유일한 면이라, 여기가 틀리면 둘 다 흔들린다.
> 지킬 것 둘: **빨간 바 계약(GDD 2장)은 한 글자도 안 바뀐다** · **sim 은 나라를 모른다**(BUILD §1-1).

## 0. 밤의 암살판 — 첫 저격 (2026-10-18, 형이 정한 꼴)

> 형: *"기존 한발 미니게임도 기와 위에서 방안으로 활을 쏴 맞히는걸 해야하지 않을까나. 타겟 에셋 인물마다 만들지 말고
> (어둠속에서 사람형체 같이 표현) 밤이니까 어두우면서 등불이나 불꽃에 따라 밝게 보이게 하고, 유한한 화살수로 3 스테이지 정도
> 준비해주고 적을 모두 사살해서 3스테이지 끝의 창호지 안에 보이는 사람의 실루엣을 쏘면 무력화 성공하는거지."*
>
> 아래 §1~§6(낮의 거점 저격)보다 **이것을 먼저 짓는다.** 공작 '암살'(plots.ts)의 판정을 이 판이 대신한다 — 안 하면 굴림(맡기기).

### 0-1. 판의 꼴

- **자리**: 자객이 **기와지붕 위**에 엎드려 아래 마당·방을 쏜다. 활터의 활·당김·탄도·빨간 바를 그대로 쓴다 (빨간 바 계약 무변).
- **쏘는 사람 = 여자 자객 궁사** (형: "암살자는 섹시한 여자 암살궁사면 좋겠네") — 공작 삽화 `event-assassin-archer` 의 그 여인.
  판 안에서는 활터 궁수처럼 **팔 없는 몸 그림 한 장** + 절차로 그리는 팔·활 (ASSETS 의 길 — 겨냥·당김이 팔에 있다). 이 판에 새로 받는 그림은 이것 하나.
- **과녁은 그림이 아니라 형체**: 사람 모양 실루엣(검은 몸 + 등불을 받는 쪽 가장자리만 밝게). 인물마다 그림을 만들지 않는다 — 크기·자세(서 있기·걷기·앉기)·들고 있는 것(창·등불)만 바꾼다.
- **어둠과 빛**: 화면 전체가 어둡고, 등불·횃불·모닥불·창호지 뒤 촛불이 둘레를 밝힌다. **빛 안에 들어온 형체만 또렷하다** — 어둠 속 형체는 흐릿한 윤곽만. 등불을 든 순찰은 빛을 데리고 다닌다.
- **화살은 유한하다**: 판 셋 전부 합쳐 정해진 수 (자객의 지략·명궁 특성으로 늘어난다 — 바탕 9발 안팎).
- **판 셋**:
  1. **담장 밖** — 보초 둘·셋, 서 있거나 짧게 오간다. 횃불 두 개.
  2. **안뜰** — 등불 든 순찰이 빛을 끌고 돈다, 모닥불 곁에 둘.
  3. **사랑채 앞** — 호위 몇, 그리고 **창호지 문 뒤 촛불에 비친 적장의 그림자**. 호위를 다 쓰러뜨려야 그림자가 문 가까이 와서 선다.
- **적장 그림자**: 머리 = 죽음, 몸통 = 중상(2계절 못 이끔) — 둘 다 "무력화". 빗나가면 그림자가 촛불을 끄고 사라진다 → 실패.

### 0-2. 발각 — 이 판의 긴장 (형의 안에 더한 것)

- **소리 게이지(경계)**: 빗나간 화살이 기와·벽·땅에 맞으면 소리가 나 게이지가 오른다. 쓰러진 시체를 다른 보초가 빛 안에서 보면 크게 오른다.
- 게이지가 차면 **경보** — 북이 울리고 적장이 달아난다 → 실패, 자객이 잡힐 굴림.
- **등불을 쏘아 끌 수 있다** — 그 둘레가 어두워져 시체가 안 보이지만, 그쪽 과녁도 안 보인다. 고를 거리.
- 화살이 떨어지면 끝 (실패, 경보는 안 울림 — 조용히 물러난다).

### 0-3. 결과 → 나라

`{ result: 'dead' | 'wounded' | 'fled' | 'withdrew', alarm: boolean }` → plots.ts 의 '암살' 판정을 이 값으로 덮는다
(dead/wounded = 먹힘, fled+alarm = 들킴, withdrew = 실패·안 들킴). 결정론: 판의 배치는 시드·계절·대상에서 굽고, 손이 쏜 결과만 바깥에서 들어온다 (SYSTEMS §6 의 snipes 와 같은 길).

**연습 먼저 · 건너뛰기 (2026-10-19, 형: "암살은 쏘기전에 연습모드 먼저 할수 있게 해줘. 건너뛰기 버튼도")** — 임무 첫 화면에서
「연습 먼저」(다른 시드의 지붕 · 같은 활·화살 · 「연습」 표 · 결과 안 보냄 · 몇 번이든) → 「진짜로 쏜다」, 또는 「건너뛰기 · 자객에게 맡긴다」.
건너뛰기는 `{ result: 'skip', seen }` 으로 와서 굴림으로 간다. 진짜 지붕에서 첫 살 전에 건너뛰면 `seen: true` — 굴림 × `plotSkipSeenMul`
(보고 고르는 맛을 막는다, BALANCE.md 2026-10-19). 첫 살을 쏜 뒤에는 건너뛰기가 없다.

### 0-4. 짓는 순서

1. 활터 sim 을 건드리지 않고 **밤 판 하나**(`src/night/` — sim·render 를 빌려 쓰는 작은 모드)를 따로 띄워 손맛부터 (형이 쏴 본다).
2. 셋 판 · 발각 · 등불 끄기.
3. 공작 '암살'에서 "직접 쏜다 / 맡긴다".

### 0-5. 지은 자리 (2026-10-18, 1·2 단계)

- `night.html` + `src/night-main.ts` (진입·돌림·판 위 DOM) · `src/night/layout.ts` (판 셋 + 연습장 '과녁만', 시드로 흔듦) ·
  `src/night/sim.ts` (형체 판정·빛·발각·판 넘김·적장) · `src/night/draw.ts` (어둠·빛·형체·창호지·글자판). 숫자는 `P.night`.
- **활 손맛은 빌렸다**: `createWorld`(과녁 없는 판, 땅 꺾은선 = 지붕 0 → 마당 −roofHeight) 위에서 `stepArcher` · `stepArrows` 만 돌린다.
  활터의 `w.targets` 는 비어 있고, 밤의 형체·불·담·창호지에 닿는 것은 sim.ts 가 그 틱의 살 선분을 5cm 마다 훑어 판정한다. 활터 sim 무변.
- **자객 몸**: `public/sprites/night-assassin.png` 를 `render/foeart.ts setHeroSkin` 으로 활터 주인공 자리에 끼운다 (턱 0.594·0.152, 어깨 0.69/0.26·0.215, 발 0.99 —
  픽셀로 잰 값). 팔은 남색 소매 + 살색 손 선. 활터는 setHeroSkin 을 안 부르므로 그대로다 (`npm run balance` HEAD 와 같음).
- **결과 길**: 임무 `night.html?seed=&arrows=&id=&back=` → 끝나면 localStorage `hanbal.night.result` = `{ id, seed, result, alarm, arrowsLeft, stage, at }`
  (틀 안이면 같은 것을 `postMessage({ type: 'hanbal.night.result', … })`). 연습장 `?practice=1` → 내보내지 않고 `hanbal.night.practice` 에 판마다 기록.
- 판정 규칙: 머리 = 소리 없음 · 몸통 = 신음(noiseGroan) · 다리 = 비명(noiseScream). 불(횃불·등불)은 맞으면 꺼진다, 모닥불은 살 셋(fireHits)에 사그라든다.
  적장이 선 뒤엔 촛불 게이지(chiefPatience)가 닳는다 — 빗나간 살은 게이지를 뭉텅(chiefMissCut) 깎을 뿐 바로 달아나지 않는다 (0-7).
- 헤드리스 프로브 `tools/probe-night.ts [seed]` — 판마다 서 있는 보초의 머리각을 찾고 같은 각 두 번이 같은 결과인지 본다.

### 0-7. 꺼진 불 · 경비 · 촛불 게이지 (2026-10-21)

형: *"안뜰에서는 뭐 통과할 방법이 없는데 … 경비가 삼엄한 암살이랑 안삼엄한거랑 조금 달라야 … 불꺼지면 경비들은 불키러 가야하는거 아님?
… 불 붙이는 중 하면서 게이지바가 나오면"* · *"사랑채에서 촛불이 꺼져서 도망치는건 대체뭔데. 어떻게잡으라는겨"*

- **안뜰이 막혀 있던 까닭** — 모닥불이 안 꺼지니 불 곁의 보초를 쏘면 시체가 늘 빛 안이라 맞은편 보초가 본다. 풀 길이 없었다.
- **꺼진 불을 다시 붙인다** (`sim.tendLights`) — 불이 꺼지면 가장 가까운 한가한 보초(relightReach)가 걸어가(go) 붙이고(light, 머리 위 게이지 「불 붙이는 중」) 제자리로(back).
  등불을 든 보초는 제자리에서 붙인다. 붙이는 동안엔 **불만 본다**(시체를 못 본다). 앉은 보초도 일어선다.
  → 불을 끄면 보초가 **어둠 속으로 혼자 걸어 나온다** — 거기서 머리를 쏘면 아무도 못 본다. 다 붙이기 전에 못 쏘면 불이 돌아와 곁의 시체가 보인다.
- **모닥불** — 살 fireHits(3)발에 사그라든다(꽂힐 때마다 불똥 소리 noiseFire · 빛이 준다). 꺼지면 불씨만 붉게 남고, 살리는 데 relightFire(×2) 걸린다.
- **경비 단계** (`layout.Guard` 0 느슨 · 1 보통 · 2 삼엄) — 판 표의 `min` 으로 사람·불이 더하고 빠진다 (보통 = 옛 배치 그대로).
  느슨: 보초 하나 적고, 붙이기 느리고(relightLoose), 눈길 짧다(sightLoose). 삼엄: 보초·횃불이 더 있고, 빨리 붙이고(relightTight), 눈길 길고(sightTight),
  **불이 꺼지기만 해도 수상히 여긴다**(darkSuspect). 칠십팔국 `plots.assassinGuard` = 고을 경계 + 도읍(guardCapital) + 군주(guardRuler) → `guard=`.
  연습장에서 고를 수 있다.
- **촛불 게이지** — 그림자가 서면 창호지 위에 게이지 + 「그림자가 일어선다 — 창호지 너머를 쏴라」. 빗나가면 「촛불이 흔들린다」.
  놓치면 결과판에 어떻게 잡는지 한 줄.
- **연습장도 지도 위 틀로** — 페이지째 넘어갔다 돌아오며 첫 화면이 뜨던 것(형: "돌아가기 누르면 … 아예 시작화면으로") 을 고쳤다.

### 0-6. 자객 기본 · 장수는 도박 (2026-10-18, 형이 고름)

형: *"암살자는 꼭 장수만 할수 있는거야? 암살 실패하면 바로 장수 잃는거고?? … 우리도 위험을 감수해야하는게 맞기는한데"*

- **고용 자객이 기본** — 곡식이 더 들고(plotHiredGrain), 들켜도 **값만 잃는다**(그 나라와는 두 칸 나빠지고 호감이 깎인다).
- **우리 장수를 보내면 도박** — 지략·명궁이 굴림을 올리고 밤 판에서 화살을 더 받는다(`plotAgentArrows` · 명궁 `archerBonus`, `plots.assassinArrows`).
  들키면 **도망과 사로잡힘을 굴린다** (`escapeChance`: 바탕 0.40 + 지략·무예 5 넘는 1마다 + 명궁·밤눈·겁 많음, 천장 0.85). 보고: `plot.agentFate`.
- **한 적장은 한 계절에 한 번** — 같은 나라가 같은 장수에게 거는 둘째 암살(둘째 손맛 포함)은 엔진이 버린다.
- **자객의 활** — 계단으로 오른다 (형: "완만한 성장이 아니라 계단적 성장"). `{kind:'bowUp'}` 로 단궁 → 맥궁 → 각궁 → 신궁,
  단계마다 곡식·철이 크게 든다(bowUp*). `plots.assassinBow(r, 나라)` 를 밤 판 `bow=` 로 넘긴다. 굴리는 암살도 단계마다 +0.08.
  AI 는 노릴 적장이 보이고 값이 남을 때 드물게 산다(aiBowUpChance).

### 0-8. 구출 — 같은 밤 판, 셋째 판에 묶인 우리 장수 (2026-10-26)

형: *"공작중에서는 잡혀간 우리 장수가있는나라의 경우 구출 이 활성화되면 좋겠어. 구출작전은 암살이랑 비슷하게 활쏘기겜으로 가서 적물리치면될듯."*

- 공작 `rescue` — 잡혀간 우리 장수가 있을 때만 대상이 생긴다 (잡은 나라가 살아 있고 우리가 아는 나라 · 그 나라 도읍의 옥 `plots.rescueNode`). 없으면 공작 칸이 흐리다.
- 보낼 이·값은 암살과 같은 결 — 고용 자객(곡식 `plotRescueGrain` + `plotHiredGrain`) 또는 쉬는 장수(도박). 굴림 = `plotBaseRescue` + 지략·명궁·활 단계 − 도읍이면 `plotRescueCapital` − 고을 경계.
- 밤 판 `night.html?…&kind=rescue&who=<이름>` — 판 셋과 보초는 암살과 똑같고, 셋째 판에 적장 대신 마루 기둥에 묶인 장수(`role: 'captive'`, 살이 비켜 간다)가 앉아 있다. 보초를 다 쓰러뜨리면 `cleared` → 풀려나 우리 도읍으로 돌아온다. 북이 울리면 `fled`(실패 · 들킴), 화살이 다하거나 그만두면 `withdrew`(실패 · 안 들킴), 건너뛰기는 굴림(`plotSkipSeenMul`). 경비는 `plots.rescueGuard`(옥 고을 경계 + 도읍).
- 들켜 누가 보냈는지 드러나면 한 칸 나빠진다 (암살은 두 칸). 풀려난 장수는 회유가 끊긴다.

## 1. 적장이라는 과녁

### 1-1. 새 종류를 만들지 않는다 — 보스 문법을 넓힌다

지금 sim 에는 이미 세 판정이 있다 (`src/sim/target.ts`):
- **급소(머리)** — `foeWeakSpot` · `bossWeakSpot` 이 자리를 주고, 화살 진행 직선이 그 원을 지나면 머리다 (`:504~525`).
- **다리** — 보스 문법 `'leg'` (폭주귀신·구미호)는 착탄이 `y < target.y − r × P.target.bossLegZone` 이면 넘어진다 (`:530`).
- **몸통** — 나머지.

적장은 **보스 문법 하나를 더한 것**이다 — `bossGrammar(look) === 'chief'`. 세 판정을 다 쓴다.
새 과녁 종류(`TargetKind`)를 만들지 않는 이유: 판정·피해·약점·연출·소리가 전부 보스 길을 타고 오기 때문에,
새 종류는 그 길을 처음부터 다시 까는 일이다.

**보스 길을 탈 때 손볼 셋** (교차 점검 2026-10-17 — 코드 확인):
- 머리 즉사(`execute`)는 지금 `kind === 'archer'` 에만 걸린다 (`target.ts:569`). 적장(보스)에도 걸어야 머리 한 발이 사살이 된다.
- 다리 판정은 비틀거리는 동안(`stagger > 0`)엔 다시 안 걸린다. '넘어져 기어감'은 새로 만드는 동작이다.
- 보스 수 `BOSS_KINDS = 8` 은 `stages.ts` 와 render 두 곳이 함께 지키는 수다 — 셋을 같이 바꾼다.

### 1-2. sim 이 더 내보내는 것 — `zone`

`hit` 사건에 `head: boolean` 이 있다. 여기에 **`zone: 'head' | 'body' | 'leg'`** 를 더한다 (head 는 그대로 둔다 — 기존 소비자가 많다).
- 나라 쪽(`game/snipe.ts`)은 sim 사건만 읽어 결과를 만든다. sim 은 "이것이 적장이다"를 모른다 — `look` 만 안다.

### 1-3. 적장의 몸

| 맞은 곳 | sim 안에서 | 판 결과에 남는 것 |
|---|---|---|
| **머리** | 즉시 쓰러진다 (적 궁수 헤드샷 즉사와 같은 규칙) | `chief: 'dead'` |
| **다리** | 넘어진다 → **기어서** 엄폐물 쪽으로 간다 (느리다) | `legged: true` |
| **몸통** 1발 | 비틀거린다 (stagger) · 체력 2 중 1 | `wounded: true` |
| **몸통** 2발 | 쓰러진다 | `chief: 'dead'` |

- **다리를 맞힌 뒤에도 머리를 쏠 수 있다.** 기어가는 적장의 머리를 맞히면 `dead` 로 바뀐다 —
  **판 안에서 "가질 것인가 죽일 것인가"를 바꿀 수 있다.** 이 마음 바꾸기가 이 판의 극이다.
- 판의 결과는 **판이 끝난 순간의 상태**다: `dead` > (`legged` + `wounded`) > `legged` > `wounded` > 없음.

### 1-4. 적장의 행동 — 특성이 판을 바꾼다

| 장수의 값 | 판 안의 모습 | 기존 재료 |
|---|---|---|
| 기본 | 망루·목책 뒤에 서 있다. 경계 시계가 다 차면 **숨는다** | 숨는 사수의 숨기 문법 |
| '신중' | 처음부터 방패 든 호위가 앞에 선다 · 시계가 20% 빠르다 | 방패 |
| '날랜 발' | **걷는다** (이동 과녁) — 다리를 맞히기 어렵다, 머리는 그대로 | 이동 과녁 (사냥 2장 · 3장 '바람과 이동') |
| '명궁' | **나를 쏜다** (보스 여덟의 자기 공격과 같은 판정) | `fireEnemyShot` · 패링(환도) |
| '겁 많음' | 첫 화살이 빗나가는 순간 숨는다 | — |
| '큰 목소리' | 북이 하나 더 있다 (북을 쏘면 호위가 흩어진다) | — |

## 2. 거점이 판을 굽는다

`game/snipe.ts` 의 `bakeSnipe(stronghold, choice, seed) → StageDef` — **순수 함수**. 같은 입력이면 같은 판.

| 거점의 값 (realm) | StageDef 의 값 (sim) |
|---|---|
| 거리 선택 (멀리 · 중간 · 가까이) | 적장까지의 x · 과녁 크기는 `stagekit` 각크기 곡선의 **판 번호 30 · 15 · 5** 에 해당하는 값 |
| 지형 꼬리표 | `ground` 꺾은선 (높은 터 → 오르막 · 갈대 → 낮은 가림) |
| 계절 | `wind` — 봄 약 · 여름 장마(시위가 눅어 사거리 −10%) · 가을 맑음 · 겨울 강풍 |
| 경계 | `timeLimit` = 기본(멀리 30 · 중간 20 · 가까이 12 초) × (1 − 경계) — 최소 8초 |
| 호위 병종 | 기존 적들: 창병 → 숨는 사수 · 궁수 → 창문 사수 · 방패병 → 방패 · 정예 → 갑옷 정예 |
| 표적 | 적장(+ 그의 특성) · 북 · 깃발 · 창고(불화살로만) |
| 화살 | `arrowFloor`(적+1) 이상 — 신궁의 바닥 규칙 그대로 (`stagekit.ts`) · 드래프트는 신궁의 화살 9종 중 군장이 가진 것 |
| 시드 | `roll(realm.seed, season, 'snipe:' + battleId)` (BUILD §1-3) |

- **난이도는 여전히 크기와 거리로 만든다** — 산포·떨림 계수는 손대지 않는다 (GDD 2장).
- 가까이를 고르면 판이 쉽고 짧다 — 대신 실패의 값이 크다 (§3).

## 3. 판이 끝나는 길과 그 값

| 끝 | 언제 | 나라에 가는 것 |
|---|---|---|
| 적장 결과가 정해졌다 | 머리 · 몸통 2발 · 다리 뒤 엄폐물 도착 | 위 §1-3 |
| 시간이 다 됐다 | `timeLimit` | 적장이 숨는다 → **경계 +0.25** · 그때까지 맞힌 북·창고·호위는 남는다 |
| 화살이 다 됐다 | | 같음 |
| 물러난다 | 플레이어가 버튼 (한 번) | 맞힌 것만 남는다 · 경계 +0.10 (들키지 않고 빠졌다) |
| 군장이 쓰러진다 | 적의 화살에 체력 0 (기존 방어 판) | **부상 굴림** — 가까이 40% · 중간 20% · 멀리 5% 로 몇 계절 쏘지 못한다 · 죽지는 않는다 |

### 3-1. 판 결과의 꼴

```ts
// game/snipe.ts — sim 사건에서 이것만 뽑아 realm 으로 넘긴다
interface SnipeResult {
  chief: 'dead' | 'legged' | 'wounded' | 'legged+wounded' | 'hidden' | 'none'
  drum: boolean            // 북을 쐈다 → 방어 −15%
  granary: 0 | 1 | 2       // 0 안 탐 · 1 탔다(−50%) · 2 바람을 등지고 탔다(−80%, WORLD §6 #27)
  guardsDown: number       // 쓰러진 호위 수 → 병력 소량
  hurt: boolean            // 군장이 쓰러졌다 → 부상 굴림
  arrowsUsed: number       // 실제로 쏜 만큼만 (GDD 5장)
}
```

- realm 은 `SnipeResult` 만 안다. 화살이 몇 도로 날았는지 모른다 — 층의 경계다.
- `granary: 2` 의 판정: 불화살이 창고를 맞힌 순간 바람이 적 쪽으로 분다(`wind` 부호). 활 sim 의 바람이 그대로 전략 결과가 된다.

## 4. 맡기기의 숫자 — `p_auto`

- 판 종류 = (거리 3) × (지형 4) × (호위 3) × (계절 4) × (적장 특성 6) = 864 칸.
- 칸마다 **평균 봇**(기존 `tools/balance-sim.ts` 의 봇)이 N=200 번 쏴서 `SnipeResult` 분포를 낸다 → 빌드 때 표로 굽는다.
- 맡기면 그 분포에서 **좋은 결과의 확률을 × 0.7** 해서 굴린다 (명궁 특성 +15%p · 명장 사미루 ×1.0).
- 이 표는 **정보의 계약**에 걸린다 — "맡기면 다리 38%" 라고 보이면 실제로 38% 다 (BUILD §3-3 보정 시험에 넣는다).

## 5. 그림과 소리

| 무엇 | 어떻게 |
|---|---|
| 적장 | 사람 몸 그림 + **칭호마다 머리 장식**(읍차 → 신지로 갈수록 크게) · 편두·문신 부품(WORLD §6 #23) |
| 망루 · 목책 · 창고 | 거점 소품 — 그림 주방 격자 한 장 (BUILD §4) |
| 북 · 깃발 | 소품 · 맞으면 북은 둥 하고 찢어지는 소리, 깃발은 꺾인다 |
| 다리 명중 | **넘어지는 몸짓**이 이 판의 가장 중요한 연출이다 — 쓰러지는 소리 + 짧은 히트스톱 + "발 묶음" 한 줄 |
| 불 | 창고 지붕에 번지는 불 · 바람을 등지면 연기가 적 쪽으로 기운다 (`granary: 2` 가 눈에 보인다) |

## 6. 저격을 쓰지 않는 사람

- **맡기기만 해도 판이 끝까지 돈다** (SYSTEMS §6-5). 저격은 숙제가 아니라 이 게임의 손맛이다 — 기본은 직접 쏜다.
- 그래도 저격이 "더 좋은 수"인 이유는 `p_auto` 의 × 0.7 하나뿐이다. 이 숫자가 1에 가까우면 저격이 장식이 되고,
  0.4 처럼 낮으면 저격이 의무가 된다. **0.7 은 R2 에서 사람 손으로 재서 정한다** — 봇의 숫자만으로 정하지 않는다.
