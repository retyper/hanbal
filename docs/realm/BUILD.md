# BUILD — 어떻게 짓는가

> ARCHITECTURE.md A1~A8 은 새 층에도 그대로 걸린다. 이 문서는 그 위에 **더하는 것**만 적는다.

## 1. 아키텍처

### 1-1. 층

```
  core  ←  sim (활)     ←┐
    ↑                    ├─  game  ←  render / input / ui
    └──  realm (나라)   ←┘     ↑
                               tune (P.bow… · P.realm…)

  realm : 지도·정보·전투 판정·장수·고을·사건·AI. DOM 모름. sim 도 모름.
  game  : 두 sim 을 잇는다 — game/snipe.ts 가 거점 → StageDef, SimEvent → 저격 결과.
```

- `src/realm/` 은 `src/sim/` 과 **같은 금지**를 받는다: `Math.random` · `Date.now` · `performance.now` · DOM.
  절대 규칙 1(CLAUDE.md)의 범위를 `src/realm/` 까지 넓힌다. guard 훅도 같이 넓힌다.
- realm 과 sim 은 서로 import 하지 않는다. 둘은 game 에서만 만난다.
  → 활을 안 건드리고 나라를 바꿀 수 있고, 나라를 안 건드리고 활을 바꿀 수 있다.

### 1-2. 계절 함수 — 순수하게

```ts
// realm/season.ts
advance(realm: Realm, orders: Orders, shots: SnipeResult[]): { next: Realm; report: Report }
```

- 입력이 같으면 출력이 같다. 안에서 아무것도 밖을 읽지 않는다.
- `Realm` 은 JSON 으로 그대로 직렬화되는 평범한 객체다 (클래스·함수·Map 금지 → 저장·비교·리플레이가 공짜).
- 고을 수십 · 장수 수십 규모라 계절마다 통째로 복사해도 1ms 안쪽이다. 핫 루프가 아니므로
  A5의 "할당 0"은 여기엔 걸지 않는다 (활 sim 에만 건다).
- 처리 순서는 SYSTEMS §12 가 단일 출처다.

### 1-3. 주사위 — 이름 붙은 흐름

```ts
// core/rng.ts 에 더한다
roll(seed: number, season: number, key: string): number   // 0..1, 해시 기반 (splitmix/xmur 계열)
// 예: roll(realm.seed, realm.season, `battle:${edgeId}:${attacker}`)
```

- 굴림마다 **이름**이 있다. 하나의 RNG 를 차례로 뽑지 않는다.
  → 판정 하나를 더해도 다른 판정의 결과가 밀리지 않는다 (콘텐츠를 더할 때마다 옛 리플레이가 깨지는 일을 막는다).
  → 다시 불러와도 같은 결정은 같은 결과 (VISION §2-3).
- **결정이 키에 들어간다**: 같은 길을 다른 장수로 치면 키가 다르다 → 결과를 바꾸려면 결정을 바꿔야 한다.

### 1-4. 저장

- 새 키 `hanbal.realm.v1` (기존 `hanbal.save.v1` 은 그대로 — 신궁의 몸·활터 진행이 거기 산다).
- 내용: **판 시작 스냅숏 + 계절마다 (명령, 저격 결과, 회유 저금)** + 최신 스냅숏.
  회유 저금(SYSTEMS §15-2)은 벽시계에서 나오지만 **계절의 입력으로 기록**한다 — 그래야 리플레이가 스냅숏과 같다.
- 저장되는 판의 상태는 **"넘기기 전"과 "넘긴 뒤" 둘뿐**이다 (SYSTEMS §12 두 단계). 반쯤 넘긴 상태는 없다.
- 저격 진행은 따로 저장한다: 판 시드 + 쏜 화살 기록 (SYSTEMS §15-4). 돌아오면 멈춘 자리에서 다시 연다.
  → 최신 스냅숏으로 바로 불러오고(VISION M8 — 3초), 기록으로는 처음부터 다시 돌려 **검증**할 수 있다 (버그 리포트 = 리플레이 한 개).
- 연대기(VISION §5-4)는 따로 `hanbal.chronicle.v1` — 판이 깨져도 연대기는 안 깨진다.
- 저장 시점: 계절 끝 · `visibilitychange` · `pagehide` (A3). 타이머 저장 금지.
- 스키마 버전 + 마이그레이션 체인 (A4).

### 1-5. 연구의 문 (R13 — 만들지 않고 열어만 둔다)

- `tools/realm-sim.ts` 는 처음부터 **CLI**로 짓는다: `--seed --bots --params params.json --out runs.csv`.
- 그러면 넷로고의 BehaviorSpace(값을 바꿔 가며 수천 번 돌려 표로 뽑기)와 같은 꼴이 저절로 생긴다.
- 공공데이터를 넣는 일, 연구용 모형은 **별개 프로젝트**다. 이 게임은 결정론·헤드리스·CSV 까지만 책임진다.

### 1-6. 콘텐츠는 데이터로

```
src/realm/data/
  regions/byeonhan.ts   지도 (고을·길·꼬리표 — 실제 지리 + 시드 변수 자리)
  traits.ts             특성 45 → 60
  heroes.ts             명장 (고정 인물 · 등장 조건 · 사연 사슬)
  events.ts             사건 카드
  prose.ts              꼬리표 문장 · 일대기 문형
  tech.ts               기술 15
```

- 글은 코드가 아니라 데이터에 둔다. 고증 검토(§3-6 lore-lens)가 코드를 안 읽고 글만 본다.
- 숫자는 데이터가 아니라 `P.realm` 에 둔다 (A2). 데이터는 "무엇", params 는 "얼마나".

## 3. 검증 — 감이 아니라 숫자로

### 3-1. 불변식 시험 (`tests/realm/`)

| 시험 | 무엇을 지키나 |
|---|---|
| 같은 시드 + 같은 명령 기록 → 같은 상태 해시 | A1 |
| 리플레이(처음부터) = 스냅숏 | 저장 정합 |
| 보이는 범위는 언제나 참값을 품는다 (소문 표식 제외) — 1만 회 | 정보의 계약 |
| 결과 칸 확률의 합 = 1 · 음수 자원 없음 · 가호 보존(이주는 옮길 뿐) | 정합 |
| 실시간 경과는 보상(회유·원정·혼인·비축)만 바꾼다 — **적의 상태 해시가 안 변한다** | **VISION §1 "남긴 것"** |
| "다음 계절"만 누르는 봇(모든 카드 기본값)이 **첫 판 전체**를 지나도 기본값 때문에 판이 끝나지 않는다 | **SYSTEMS §15-1** |
| 실시간으로만 찬 회유 막대는 탈출·자결을 내지 않는다 · 한 번 비울 때 상한(4칸)을 넘지 않는다 · 원정 결과는 보낼 때 정해진다 | **SYSTEMS §15-4** |
| 저격을 닫았다 열면 같은 판이 같은 자리에서 열린다 (화살 기록 재생 = 같은 상태) | **VISION §2-3 · SYSTEMS §15-4** |

### 3-2. 저격 자동 판정 표

활 봇이 생성된 저격을 판 종류(거리 × 지형 × 호위 × 계절 × 적장 특성 = 864칸, SNIPE §4)마다 N=200번 쏘고 결과 분포를 낸다 →
`p_auto = 평균 봇 분포 × 0.7`. 표는 빌드 때 구워서 데이터로 넣는다 (게임 중에 봇을 돌리지 않는다).

### 3-3. 보정 시험 (정보의 계약의 숫자 쪽)

화면에 `p` 로 보인 판정 1만 건을 모아 10칸으로 나눠, 칸마다 **실제로 일어난 비율과 2%p 안**이어야 한다.
XCOM 이 사람들의 신뢰를 잃은 바로 그 자리를 시험으로 막는다.

### 3-4. 몰입 봇 — "한 계절만 더"를 잰다 (VISION M1·M2)

재미가 1순위가 되면서 이 봇이 재는 것이 뒤집혔다 — 예전엔 "걸린 것 없이 끝나는 계절"을 늘리려 했고, 이제는 **줄이려** 한다.
- **걸린 것이 있는 계절의 비율 ≥ 95%** — 계절 끝에 "다음 계절에 —"를 말할 수 있는가 (SYSTEMS §15-2)
- **터지는 순간의 간격** — 슬롯 결과 중 '드묾' 이상이 평균 **3~5계절마다** 하나. 너무 잦으면 값이 떨어지고, 너무 드물면 손이 멈춘다
- **같은 클릭의 되풀이** — 결정 없이 같은 버튼만 누르는 계절이 3연속을 넘지 않는다 (M3)
- 저격·전장: 판당 직접 쏘는 판 **6~15번** · 전장 **3~8번**
- 첫 판(변한) **55~70 계절** · 3~6시간
- 그리고 **형의 손** — 숫자는 봇이 재고, 재미는 형이 판정한다. R1 종이 시험부터 매 마일스톤 끝에.

### 3-5. 전략 균형 — "신중함이 이긴다"를 잰다 (R7)

| 봇 | 하는 짓 |
|---|---|
| 무모 | 정찰 없이 가장 약해 보이는 곳을 친다 |
| 신중 | 정보가 a ≤ 1 이고 승률 ≥ 0.6 일 때만 친다 · 겨울 결빙과 제천을 노린다 |
| 수집가 | 생포를 최대화한다 (다리를 쏜다 · 퇴로를 끊는다) |
| 장사꾼 | 철길 승리를 노린다 |
| 무작위 | 기준선 |

합격선 (초안):
- **신중 봇의 승률 − 무모 봇의 승률 ≥ 25%p** — 이것이 안 나오면 정보 체계가 장식이다.
- 정복 · 추대 · 철길 중 어느 하나도 최적화된 봇들의 승리의 60% 를 넘지 않는다 — 한 길만 정답이면 안 된다.
- 수집가 봇은 승률이 신중 봇보다 낮되(가지려면 위험을 진다) **같은 전투 수에서 생포가 2배 이상**.
  (검산: 지금 초안은 1.34배 — 수집량은 생포율보다 전투 횟수가 정한다. R3 에서 다리 명중·퇴로의 값을 다시 잰다.)
- **종이 검산 기록**: balance-lens 2026-10-17 — 스크립트는 `docs/realm/calc/` 에 옮겨 두었다 (예전 초안 수치 기준). 고친 것은 SYSTEMS 의
  "(검산: …)" 줄들이 남긴다. R1 의 `tools/realm-sim.ts` 가 생기면 이 검산을 그 위에서 다시 돌린다.

### 8-2. Q12 — 서버와 계정 (2026-10-21)

**왜 따로 노나.** 판은 그 브라우저의 localStorage 에만 있다. 아이폰은 사파리와 홈 화면 앱의 저장소가 따로이고,
안드로이드도 크롬·카카오톡 안 창·삼성 인터넷이 따로다. 폰과 피시는 말할 것도 없다. 깃허브 페이지는 파일만 내주니 받아 둘 곳이 없다.

**지금 저장 칸** (realm 만): `hanbal.realm.v2`(+ `.prev`) 판 · `.draft` 이번 계절 명령 · `.dex` 도감 · `.clan` 혈통 · `.retain` 계승 가신 ·
`.unlock` 판 해금·난세 단계 · `.games` 판 기록(크다) · `.tut` `.seen` `.layers` `.mute` 기기 설정.
→ 옮길 것은 **판 · 명령 · 도감 · 혈통 · 계승 · 해금** 여섯. 판 기록은 커서 빼거나 따로(형 판 기록 원칙은 기기에 남는다), 설정은 기기마다.

**짓는 모양 — 로컬이 먼저, 서버는 뒤따른다**
- 판은 지금처럼 기기에서 돈다(A1 결정론 · 오프라인 · 3초 복귀). 서버는 "마지막으로 맞춘 한 벌"을 들고 있을 뿐 — 엔진은 서버를 모른다.
- 한 계정에 한 벌: `{ v, savedAt, device, realm, draft, dex, clan, retain, unlock }` JSON 하나. 계절 넘길 때·앱 닫을 때 올린다.
- 맞추기: 도감·혈통·해금은 **늘기만 하는 것**이라 합친다(큰 쪽). 판은 하나만 산다 — 다른 기기 것이 더 새것이면
  "이 기기 판(사로국 · 열두째 계절) / 저 기기 판(구야국 · 셋째 계절) — 어느 쪽으로?" 두 카드로 고르게 한다. 몰래 덮지 않는다.
- 로그인 안 해도 다 된다(손님). 로그인하면 그때부터 맞춘다.

**스토어가 요구하는 것**
- 애플 4.8: 구글 로그인을 두면 **애플 로그인도** 같이 둬야 한다.
- 애플 5.1.1(v) · 구글 플레이: 계정을 만들 수 있으면 **앱 안에서 계정 지우기** 가 있어야 한다(플레이는 웹 주소로도).
- 개인정보 처리방침 주소 · 스토어의 데이터 안전 항목(이메일·게임 진행만 받는다).

**어디에 둘까 (형이 정할 것)**

| | 로그인 | 저장 | 돈 | 일 |
|---|---|---|---|---|
| **① 파이어베이스** (권함) | 구글·애플 로그인을 대신 받아 준다 | Firestore 문서 하나 | 무료 칸(하루 읽기 5만)이면 한참 간다 | 웹 묶음엔 SDK 를 안 넣고 REST(fetch)로 — A6 의존 0 유지. 앱 껍데기에만 로그인 플러그인 |
| ② 클라우드플레어 워커 + D1 | 구글·애플 토큰 검사를 직접 짠다 | D1 한 줄 | 무료 칸 넉넉 | 코드는 다 우리 것 · 로그인 부분이 손이 많이 간다 |
| ③ 플레이 게임즈 · 게임센터 저장 | 각 스토어 계정 | 각자 | 0 | **아이폰↔안드로이드↔웹은 안 맞는다** — 형의 지금 문제를 못 푼다 |

- A6 세 질문(① 기준): 맞추기 코드 200~300줄 · 웹 묶음 +0KB(fetch 만) · 결정론 무관(저장은 엔진 밖, realm-main 에서).
- 서버가 생기면 따라오는 것: Q10 의 「오늘의 난세」 기록 · 형 판 기록을 내보내기 없이 받아 보기.
- 계정·프로젝트 만들기는 형이 한다(구글 계정 · 애플 개발자 계정 연 99달러 · 구글 플레이 25달러 한 번).

**짓는 차례**
1. 저장 한 곳으로 — 흩어진 localStorage 읽기·쓰기를 `realm/store` 하나로 모으고 "여섯 칸을 한 벌로 내보내기/들이기"를 만든다. 서버 없이도 쓸모 있다: 나라 판에 **판 옮기기**(글자 묶음 복사 → 다른 곳에 붙여 넣기).
2. Capacitor 껍데기 + 앱 저장소(§8-1 의 1번)를 같은 `store` 밑에 붙인다.
3. 서버(형이 고른 곳) · 로그인 · 맞추기 · 계정 지우기.
