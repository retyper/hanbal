# 신궁 (神弓) — 게임 설계 문서

> 스틱맨 궁수 성장 게임. 공부 사이사이에 켜두고, 3초 안에 한 발 쏘고, 다시 공부로 돌아가는 게임.

---

## 0. 한 줄 정의

**활 한 번 안 잡아본 스틱맨이 진짜 궁수가 되어가는 과정을, 30초짜리 판으로 잘라 놓은 게임.**

---

## 1. 설계 제약 (Non-negotiable)

이 게임은 "공부의 곁"에 존재한다. 아래 제약은 재미보다 우선한다.

| # | 제약 | 검증 방법 |
|---|------|-----------|
| C1 | 탭 복귀 후 **3초 안에 첫 발**을 쏠 수 있다 | 로딩 스플래시 금지. 마지막 상태 복원. 튜토리얼 스킵 가능 |
| C2 | **아무 때나 끊어도 손해가 없다** | 자동 저장. 타이머 페널티 없음. "접속 안 하면 손실" 구조 금지 |
| C3 | 게임이 **공부를 방해하지 않는다** | 소리 **기본 ON**(낮은 볼륨) + `M` 즉시 음소거 + **성장 화면의 체크박스**(마우스 전용 경로, C5) + 선택 기억. 탭이 숨으면 sim·오디오 **즉시 정지**. 알림/뱃지 푸시 없음 |
| C4 | **돌아오면 항상 쓸 게 쌓여 있다** | 오프라인 축적. 단, 상한 있음(아래 5장) |
| C5 | 한 손(마우스)만으로 다 된다 | 키보드는 보조. 커피잔 든 채로 플레이 가능 |
| C6 | **전송 gzip 110KB · 파싱 raw 300KB** 미만, 첫 페인트 0.3s 미만 | `npm run budget` (build·CI가 부른다) |

> **C3의 소리 정책이 바뀐 이유 (2026-08-23)**: 원래 "소리 기본 OFF"였다. 형이 소리를 직접 요청했다.
> 기본 OFF면 켜는 사람이 없어 GDD 7장(연쇄 리듬·붕괴 예고의 청각 채널)이 통째로 사문화된다.
> 대신 방어를 넷 건다 — 낮은 기본 볼륨(0.38) · `M` 한 키로 즉시 음소거 · 그 선택을 localStorage에 기억 ·
> **탭이 숨는 순간 AudioContext까지 suspend**. "공부를 잡아먹지 않는다"는 조건은 그대로 지킨다.

> **C2·C3의 이유**: 이 게임의 실패 모드는 "재미없음"이 아니라 **"공부를 잡아먹음"** 이다.
> 소셜 게임식 리텐션 장치(로그인 스트릭, 접속 안 하면 시드는 밭, 타이머 압박)는 전부 금지.

> **C6의 자가 바뀐 이유 (2026-08-25)**: 원래 "**raw 150KB**" 하나였다. 형의 판단:
> *"크기 굳이 꾸역꾸역 작게 제한할 필요 없어."* 실측해보니 그 자가 틀린 것을 재고 있었다.
>
> - 150KB는 **GitHub Pages의 한계가 아니다.** Pages는 저장소 1GB·월 대역폭 100GB다.
>   호스팅이 우리를 조인 적이 없다. (그래서 Vercel 등으로 옮겨도 1바이트도 안 바뀐다.)
> - 유저가 첫 방문에 실제로 받는 건 **압축된 바이트**다 — raw 177.7KB가 gzip 65.2KB다.
>   raw로 세면 유저가 내지 않는 값으로 우리를 조르는 셈이다.
> - 그렇다고 raw를 안 셀 수는 없다. **파싱은 raw 바이트로 한다** — 저사양 기기의 CPU가
>   내는 값이 그것이다. 둘은 서로 다른 것을 지키므로 **자도 둘이어야 한다.**
>
> **그래도 상한을 없애지는 않는다.** 이 숫자의 진짜 일은 로딩 속도가 아니라
> **"런타임 의존성 0개"의 방아쇠**다 (ARCHITECTURE A6). 세는 걸 그만두면 언젠가 게임
> 엔진이 들어온다. 상한의 존재 이유는 *뭘 붙이기 전에 한 번 다투게 만드는 것*이다.
>
> 그리고 이 줄은 그동안 **거짓말이었다** — "CI에서 측정"이라고 적혀 있었지만 `deploy.yml`에
> 그런 단계가 없었고 사람이 손으로 세고 있었다. `tools/budget.ts`가 이제 실제로 막는다.

## 2. 핵심 판타지 — 활은 원래 어렵다

실제 국궁/양궁 초보가 겪는 것들을 그대로 2D로 옮긴다. 이게 이 게임의 유일한 차별점이다.

| 실제 경험 | 게임 표현 |
|-----------|-----------|
| 시위가 안 당겨진다 | **만작은 1.0이 아니라 이 궁수의 한계(`maxDraw`)다.** STR 0이면 0.72에서 팔이 멈추고, 그게 그의 만작이다. STR 14쯤에 진짜 만작(1.0)이 열린다 — 성장의 가장 큰 체감 지점 |
| 만작 유지가 몇 초 안 된다 | `STAMINA` 게이지. 초보는 붕괴까지 약 4.2초지만, **정확한 채로 버티는 건 만작 후 1.64초**뿐이다(빨간 바). 0이 되면 스틱맨이 **스스로 놓아버림**(붕괴) |
| 오래 겨누면 손이 덜덜 떨린다 | `tremor` — **스태미나가 빨간 바를 넘어 내려간 만큼만** 떨린다. 그 위에서는 시간이 아무리 흘러도 정확히 0이다. 넘긴 뒤에는 `strain`(0=경계선, 1=완전 소진)에 비례해 자라며, 완전 소진에서 화면 진폭 9px에 닿는다 |
| 숨을 참으면 잠깐 안정된다 | 호흡정지(steady). tremor 급감, 대신 스태미나 급소모 — **빨간 바에 더 빨리 닿는다** |
| 놓는 순간이 전부다 | 빨간 바를 넘긴 뒤에는 **떨림 위상**이 실제 발사각을 결정. "흔들림이 중앙을 지날 때 놓기"가 자연 발생하는 스킬 |
| 쏘고 나면 팔이 아프다 | 연사 시 회복 지연. 판 사이 자동 회복 |
| 어느 날 갑자기 는다 | 영구 스탯 성장. 되돌아가지 않음 |

**중요**: 이건 타이밍 미니게임이 아니다. QTE 링, 정확도 바 같은 UI 장치를 쓰지 않는다.
플레이어는 **스틱맨의 팔이 실제로 떨리는 걸 눈으로 보고** 놓는다. 물리가 곧 UI다.

---

### ★ 빨간 바 (the red bar) — 이 게임의 계약

> **안전 구간 안에서 만작으로 놓으면 조준한 그대로 맞는다.**
> **오차는 반드시 플레이어의 선택의 결과다.**

이건 손맛 취향이 아니라 **깨면 안 되는 약속**이다. 2026-08-23, 사용자의 한 문장에서 나왔다:
> *"일반적으로 이렇게 유저가 쏘는대로 안 맞으면 화날 거 같다."*

제대로 쐈는데 빗나가면 플레이어는 자기가 뭘 잘못했는지 알 수 없다. 배울 것도, 고칠 것도 없다.
그래서 **빗나감에는 반드시 본인이 한 선택이 앞서 있어야 하고, 그 경계가 화면에 그려져 있어야 한다.**

| | 규칙 |
|---|------|
| **빨간 바의 위치** | 최대 스태미나의 **55%** (`P.stamina.steadyZone`). 게이지 위에 세로선으로 그려지며, 게이지에서 위아래로 삐져나오는 건 이것 하나뿐이다 |
| **안전 구간 (바 위)** | 떨림 **정확히 0** · 릴리즈 산포 **정확히 0** · 조준한 그 자리에 맞는다. 실측 발사 각오차 RMS **0.000 mrad** |
| **경계선 아래** | `strain = (빨간바 - 스태미나) / 빨간바` 가 0→1로 자라고, **떨림과 오차가 전부 여기 비례한다** |
| **만작이 아니면** | 안전 구간이어도 오차가 있다 (`P.bow.partialDrawPenalty`). 덜 당기고 쏜 것도 플레이어의 선택이다 |
| **안전 구간의 폭** | 만작 도달 후 STAMINA 0에서 **1.64초**, 10에서 2.48초, 25에서 3.55초 — STAMINA가 넓힌다 |

즉 플레이어가 빗나가는 이유는 셋뿐이고, 셋 다 본인이 한 일이다:
**① 조준을 잘못했다 ② 망설이다 바를 넘겼다 ③ 덜 당기고 쐈다.**

**따라서 난이도는 산포·떨림 계수(`releaseScatter`·`baseAmp`·`steadyZone`)를 키워 만들지 않는다.**
그건 이 약속을 되돌리는 짓이다. 난이도는 언제나 과녁을 **작고 멀게** 만들어서 낸다 (6장).

화면 쪽 표현은 셋이 같은 순간에 겹친다 — 게이지의 청록(안전)이 사라지고, 경계선에서 흰 섬광이
터지고, 조준 확신 표식의 잠김 점이 꺼진다. 소리로도 그 순간부터 긴장음이 차오른다.

## 3. 조작

| 입력 | 동작 |
|------|------|
| 마우스 이동 | 조준 |
| 좌클릭 홀드 | 시위 당김 (놓는 순간 발사) |
| 우클릭 / Shift 홀드 | 호흡정지 — tremor 감소, 스태미나 급소모 |
| `R` | 판 재시작 |
| `Tab` | 성장 화면 열고 닫기 (여는 동안 sim 정지) |
| `M` | 음소거 토글 |
| `Esc` | 일시정지 (탭 나갈 때 자동) |
| 방향키 + Space | 키보드 전용 대체 조작 (접근성) |

한 발의 흐름: **겨눔 → 당김 → 놓음 → 궤적 → 명중**. 평균 4~6초.

당김은 0.38초면 끝난다(초반은 쭉 당겨지고 마지막 한 뼘이 버겁다). 그래서 이 게임의 리듬은
**"조준하며 빠르게 당긴다 → 빨간 바를 넘기기 전에 놓으면 그대로 맞는다 → 망설이면 벌받는다"** 이다.
싸움터는 당기는 구간이 아니라 **만작과 빨간 바 사이의 1.6~3.6초**다.

## 4. 성장 스탯 (영구, 되돌아가지 않음)

| 스탯 | 이름 | 효과 | 체감 |
|------|------|------|------|
| `STR` | 근력 | 최대 당김 한계(만작), 화살 초속·사거리 | "이제 시위가 끝까지 당겨진다" |
| `STEADY` | 정확 | 빨간 바 **아래**의 tremor 진폭 감소 (안전 구간은 이미 0이라 손댈 게 없다) | "넘겨도 덜 떨린다" |
| `STAMINA` | 지구력 | 최대 스태미나 → **안전 구간이 넓어진다** (1.64s → 3.55s @25), 회복 속도 | "여유 있게 겨눌 수 있다" |
| `FOCUS` | 집중 | 호흡정지 깊이·**한계 시간** (산포는 0이 되어 이 축에서 빠짐, 2026-08-24) | "결정적인 순간을 잡는다" |

> STAMINA의 효과가 "만작 유지 시간"에서 **"안전 구간의 폭"**으로 바뀐 게 재설계의 핵심이다.
> 붕괴까지 얼마나 버티는가는 이제 플레이어가 다투는 값이 아니다 — 다투는 건 빨간 바다.

성장 재화: **훈련치(training)** — 오프라인 축적 + 플레이 획득.

**훈련치를 쓰는 곳** (2026-09-02 — 형: "돈 쓸 곳을 좀 더 많이. 돈을 벌고 싶어지도록"). 축이 전부 다르다:

| 자리 | 축 | 어디서 |
|---|---|---|
| 스탯 넷 | 영구 · 몸 | 성장 화면 · 재정비 |
| 대장간(활 개조 — 시위·활채·줌통, 각 3단) | 영구 · **활마다** | 성장 화면 · 재정비 |
| 부적(살통·철갑·노다지·파귀, 하나만) | **여정 한 번** | 출정 |
| 살 가게(발견한 특수살) | 재고 | 출정 |
| 방패 · 두정갑 · 화살 한 발 | **지금 이 판** | 장터 버튼줄 (판 도중) |

버는 쪽에도 사건이 하나 있다 — **금관 사수**(12판+): 머리를 맞혀 눕히면 현상금. docs/GAP.md §9.
성장 곡선: 초반 급성장 → 후반 완만. `docs/BALANCE.md` 참조.

## 5. 오프라인 축적 (복귀 동기)

공부하는 동안 자동으로 쌓인다.

| 자원 | 축적 속도 | 상한 | 용도 |
|------|-----------|------|------|
| 화살 | 1발 / 90초 | 40발 (=1시간) | 판에 지급 · **실제로 쏜 만큼만** 소모 |
| 훈련치 | 1 / 3분 | 20 | 스탯 성장 |
| 의뢰 | 1건 / 25분 | 4건 | 특수 스테이지 (보상 큼) |

**설계 원칙**
- 상한 도달 시 **낭비 알림을 하지 않는다.** (C3) 돌아왔을 때 조용히 가득 차 있을 뿐.
- 오프라인 축적을 **끄는 옵션**을 제공한다. 끄면 스테이지 보상이 그만큼 상향.
  → "게임이 시간을 인질로 잡는다"는 느낌을 없애기 위함.
- 25분 의뢰 주기는 뽀모도로와 우연히 맞는다. 강요하지는 않는다.
- **화살은 잠금장치가 아니라 여유분이다** (2026-08-23 확정). 보유분이 넉넉하면 스테이지가 정한
  5~7발을 온전히 받고, 바닥나면 **스테이지 요구에 붙은 바닥**(`stage.arrows − spareCut`, 최소 `minArrows`)만 받아
  빠듯하게 쏜다. 바닥이 상수 3발이면 3명중을 요구하는 판에서 병목이 아니라 벽이 된다 (실측 클리어율 16%). 보유 0이어도 판은 언제나 돈다 —
  "화살이 없어 아무것도 못 함"은 9장이 금지한 에너지 게이트다. 소모도 진입 과금이 아니라
  **실제로 쏜 만큼**이다. 판을 켜놓고 자리를 뜬 사람이 손해를 보면 C2 위반이기 때문.

## 6. 판(스테이지) 구조

- 1판 = **화살 5~8발 = 30초~1분**
- 챕터 = 10판. 챕터마다 새 메커닉 1개.
- 판 끝 = 즉시 결과 → **한 번의 클릭으로 다음 판** (결과 화면에서 머무르게 하지 않는다)

### 챕터별 도입 메커닉 (초안)

| 챕터 | 메커닉 | 배우는 것 |
|------|--------|-----------|
| 1 | 정지 과녁, 가까움 | 당김·놓음 |
| 2 | 거리 증가 + 중력 낙차 | 위로 조준하기 |
| 3 | 스태미나 압박 (시간제한) | 오래 겨누지 않기 |
| 4 | 바람 | 편차 읽기 |
| 5 | 이동 과녁 | 리드 샷 |
| 6 | **공중 과녁 + 연쇄 낙하** | 순서 설계 |
| 7 | 관통 (일직선 정렬) | 각도 계산 |
| 8 | 작은 과녁 / 어둠 | 호흡정지 활용 |
| 9 | 튕김(리코셰) | 반사각 |
| 10 | 종합 + 보스 과녁 | 전부 |

이후 무한 모드: 절차 생성, 난이도 곡선으로 위 요소 조합.

## 7. 손맛 레이어 (연쇄 폭발)

공중 과녁(등불/도자기/풍선)을 맞히면 **낙하하면서 아래를 연쇄로 침** → 보로로로록.

- 콤보 배수: 연쇄 1개당 ×1.15, 상한 없음
- 히트스톱: 명중 순간 40ms 정지 (연쇄는 25ms)
- 카메라: 명중 시 미세 shake, 대형 연쇄 시 잠깐 줌아웃
- 슬로모: 마지막 화살이 결승 과녁으로 향할 때만 (남발 금지)
- 사운드 피치: 연쇄가 이어질수록 반음씩 상승 (소리는 기본 ON — 1장 C3 참조, `M`으로 끈다)

**절제 원칙**: 화면을 숫자로 덮지 않는다. 콤보 수치는 작게, 대신 **소리와 리듬**으로 느끼게.

## 8. 아트 디렉션

- **스틱맨**: 벡터 라인. 관절 5개(어깨/팔꿈치/손목/골반/무릎)로 실제 사법(射法) 자세 재현.
  세 신호가 서로 잡아먹지 않도록 **문법을 갈랐다**:
  **굵기 = 당김·성장**(만작 시 등근육 긴장) · **형태 = 빨간 바 넘김**(잠금이 풀린다: 팔꿈치·고개·활 휨) ·
  **색 = 붕괴 임박**(주저앉는다: 척추·골반·무릎). 떨림은 어깨를 축으로 한 각 오프셋이라 활 끝에서 가장 크게 나타나고,
  안전 구간에서는 **정확히 0px**이다.
- **배경**: 단색 그라디언트 + 원경 실루엣 2겹. 색 수를 극도로 제한.
- **강조색**: 과녁과 화살 궤적에만. 나머지는 무채색.
- **궤적**: 발사 후 얇은 잔상 페이드. 명중 실패 시에도 궤적이 남아 "왜 빗나갔는지" 읽힌다. (학습성)
- **다크 모드 기본**. 공부하다 눈 아프지 않게.
