3. **소리가 안 나던 것** (형: "왜 소리가 안나는지 모르겠다"). 자동재생 정책상 첫 제스처가
   있어야 AudioContext가 열리는데, 그 제스처를 **캔버스에서만** 듣고 있었다. 폰에서 첫 터치는
   거의 언제나 **DOM 버튼**(아래 조작 바·갈림길 카드·성장 화면)이라 캔버스에 안 닿고,
   그러면 그 세션의 소리가 통째로 조용히 사라진다. 이제 **창 전체에서 캡처 단계로** 듣는다.
   → 그래도 조용하면 성장 화면의 '소리 (M)' 체크를 봐라. M 키로 한 번 끄면 그 상태가 저장된다.

4. **만작에 '삥' 소리** (형: "최대로 당겨졌을때 (…) 동시에 소리도 뭔가 작게 '삥' 하는 소리").

   반짝이는데(rig.flash) 귀에는 아무것도 안 왔다. 그 섬광과 같은 순간에 2100Hz 85ms 맑은 한 톨을
   얹는다. 작게 — 크면 만작이 상으로 들려 매번 끝까지 끌게 된다.

5. **집중(集中) 게이지를 걷어냈다** (형: "당기는 힘 떨어지는 바 밑에 뭔가 하나 바가 더 생겼는데
   그거 필요없을듯. 지워버려" · "집중이 원래 기존 숨참기 아니었어?? 왜 들어간거야 지워").

   막대 · 탄도 보정 · 소리 · 노브(P.focus) · 프로브 · 테스트까지 통째로 뺐다.
   발사각은 다시 **겨눈 방향 그대로**다. 간극은 docs/GAP.md 6절에 열린 채로 남겼다.

   그림자·궤적 taper·촉 앞의 공기도 같이. `probe-sky`가 장마다 몸 대비 ≥5:1을 잰다 (실측 7.1~12.9).
7. **'한 발' 순간** — 마지막 하나를 향해 내 화살이 나는 동안만 시간이 0.4배로 늘어진다.
   히트스톱과 같은 급이라 결정론은 무사하다.
8. **살의 물리를 질량 하나에서 파생** (§11, 형: "데미지는 화살 속도랑 무게에 따라도").
   살마다 손으로 박던 speedMul·dragMul·dmgMul·pierceExtra·armorPierce를 없애고
   **질량과 단면적 둘만** 저작한다. 초속 `1/√(m+Mv)` · 항력 `A/m` · 피해 `m·v²` ·
   관통력 `(m/A)·v`. 가상질량이 없으면 총구 에너지가 모든 살에서 같아진다(실측 64 vs 65).
   교차표: homing 27→16(지배 깨짐) · pierce 0→11(죽은 카드 부활).
   갑옷 몸통 처치: 보통 살 0/4 · 애기살 3/4(5발) · 육량전 3/4(3발).
9. **점수 팝 → 피해 팝** (형: "화살이 맞으면 점수가 아니라 데미지가 떠야").
   체력 없는 과녁에는 아무 숫자도 안 띄운다. 갑옷에 튕기면 '막혔다'.
   8번의 물리가 화면에 보이는 유일한 창이 이 숫자다.
10. 곁다리 수리 — **활 그립**(당길수록 활이 손에서 도망가던 것) · **건물**(적이 죽으면
    같이 사라지던 것) · **적 궁수**(활이 몸 옆에 못박혀 있던 것) · **스테이지 머리글**
    (흩어진 점 열 개 → 장-판 쌍 + 트랙) · **몸 전체가 두꺼워지던 것**(이제 몸통만 1.17배).

**남은 것 (당시 기준)**: 갈림길 2택(판마다 결정 하나 — MEGAHIT §3, **2026-08-26 추가 7에서
완료**). 육량전은 갑옷을 열지만

### 2026-08-25 추가 5 — 발사음 재작 (형: "활 쏘는 게 병아리 소리도 아니고")

원인이 둘이었고 둘 다 소리의 **설계** 문제였다.

1. **몸통이 없었다.** 릴리즈가 삼각파 420→160Hz 하나였다. 진짜 활 소리를 지배하는 건
   시위가 아니라 **림이 브레이스로 되돌아가며 치는 저역 텅**(80~200Hz)인데 그게 통째로
   빠져 있었으니 가슴에 오는 게 없고 중역 삑만 남았다.
2. **쉭이 거꾸로 올라갔다.** swoosh 1500 → **3200**Hz. 멀어지는 화살은 음이 내려간다.
   올라가는 노이즈 스윕은 물리적으로 '다가오는 것'이라 활 소리가 될 수 없다.

그래서 릴리즈를 실제 활의 세 겹으로 다시 세웠다 — **텅**(림의 저역: 사인 210→78 +
저역 노이즈) · **탁**(시위 크랙: 밴드패스 1750→900, Q 3.4, 35ms) ·
**쉭**(밴드패스 5200→**1100**, Q 6, 200ms — 내려간다).

살별 목소리도 음정(오실레이터)에서 **바람(필터 노이즈)** 으로 옮겼다.
- **애기살=편전** (형이 직접 짚은 것): 사각파 2300→3100Hz 30ms 삑이었다. 편전은 통아에
  얹어 쏘는 반 길이 살이라 초속이 두 배 가까우니, 서명은 '더 높고 좁고 빠른 쉭'이다.
  통아 나무 틱 + 7200→1800Hz Q9 쉭 + 3000→1150Hz Q12 꼬리.
- 육량전: 저역 노이즈 몸통 + 느린 저역 쉭(1700→480). 편전과 정반대 축.
- 세전: 삼각파 3연타 → 어긋난 쉭 셋(4200/3600/3000Hz).
- 화전: 심지 파직임 아래에 불길이 끌리는 후욱(760→300)을 깔았다.
- 신전: 저역 받침 추가. 명적은 **손대지 않았다** (형: "설정 자체가 그러니까").

`probe-audio.ts`에 발사음 판정 추가 — ① 300Hz 아래 몸통이 있는가 ② 노이즈 스윕이
**내려가는가** ③ 2kHz 위 60ms 삑(=병아리)이 없는가. 7종 전부 통과, 편전 7200Hz >
기본살 5637Hz. 붐빔(편전+명중+연쇄) 동시 14개 < 상한 18.

곁다리: `probe-render.ts`의 깃발 검사가 **거짓말을 하고 있었다** — 천 색이 #c99a5e로
바뀐 걸 모르고 옛 #c96f4a로 찾아 "바람 깃발 없음 ⚠"을 4건 띄웠다. 깃발은 멀쩡했다.
고치니 2·4·6 m/s에서 -44°→-16°→0°로 제대로 눕는다.

**형이 귀로 판정해야 하는 것**: 텅·탁·쉭의 비율(P.audio의 releaseGain / releaseBodyGain /
releaseSnapGain / swooshGain 넷이 그 노브다), 편전의 쉭이 충분히 날카로운가.

**형이 눈으로 봐야 하는 것**: 창밖으로 내민 활의 각도, 건물의 층수 느낌, 머리글의 크기감.

## 2. 갈래 화살 버그 — 원인과 수정

`src/sim/ballistics.ts`

명중으로 죽은 부모 화살은 그 순간 **풀에서 가장 앞선 빈 슬롯**이 된다.
자식 배정(`freeSlot`)이 부모를 배제하지 않아서 첫 자식이 부모 슬롯에 앉았고,
`launch()`가 그 슬롯의 `pendX/pendY`(태어날 자리)를 0으로 지웠다.
그래서 **두 번째 자식부터 월드 원점(0, 0) = 궁수 발치**에서 태어났다.

수정은 둘이다 (하나만으로도 되지만 빗장은 둘이어야 한다):
1. `freeSlot(w, except)` — 부모 슬롯을 배정 대상에서 뺀다.
2. `spawnSplit`이 부모의 값을 **루프 전에 복사**한다.

회귀 테스트 `tests/arrows.test.ts` — 예전 코드에서 발사점 `(0.000, 0.000)` 재현 확인.

부수 효과: 부모의 시체가 살아남아 유령 궤적(`captureTrail`)도 제대로 잡힌다.
`npm run probe` 의 화살 비교표에서 분열 살이 6개 중 3개 제거로 올라왔다.

## 3. 무한 구간 (41판~)

`src/game/endless.ts` · 공용 킷 `src/game/stagekit.ts`

- 테마 10종: 사열 · 기둥 · 진자 · 관통줄 · 아치 · 군집 · 계단 · 바람골 · 고리 · 폭풍
- **결정론.** 배치 난수는 `seedFrom('hanbal.endless.layout.' + 판번호)` 하나에서 나온다.
  sim의 `w.rng`(릴리즈 산포)와 완전히 분리돼 있다 (A1).
- **한 바퀴(10판)에 모든 테마가 정확히 한 번씩.** 블록 셔플 + 경계 보정이라
  같은 테마가 연달아 나오는 게 구조적으로 불가능하다. 테스트로 고정했다.
- 각크기는 `stagekit.angularSize()` 가 h=0.012 → 0.008 로 40판에 걸쳐 내리고 거기서 멈춘다.
  **크기로 어렵게 만들지 않는다** — 형이 한 번 반려한 방향이다.
- 화살은 "직접 맞혀야 하는 수(shots) + 2". 연쇄 판에서 화살이 남아돌지 않게.

밸런스 시뮬로 벽 세 곳을 찾아 고쳤다 (`npm run balance -- --endless=30`):

| 판 | 증상 | 원인 | 수정 |
|---|---|---|---|
| 41+5 | 클리어 0% | 기둥 3열 = 과녁 12개인데 화살 상한 10 | 열을 2로 고정, shots를 `과녁수 - 열수`로 |
| 41+16 | 클리어 5% | 같은 원인 | 위와 같음 |
| 41+17 | 클리어 20~34% | 이동 과녁 4개 + 주기 0.43Hz | 3개로 고정, 주기 상한 ↓, 크기 +30% |

지금은 표본 30판 전부 66% 이상. (대부분 봇 기준으로는 쉬운 편인데,
"앞 구간은 쉽게"라는 정책과 봇이 사람의 체감을 못 재는 한계를 감안한 의도적 선택이다.)

## 4. 소리

`src/audio/synth.ts` 의 `bellTone()` — **배음이 여럿이고, 위 배음이 먼저 죽고, 정수배가 아니다.**
이 셋이 "울리는 소리"의 전부다. 오실레이터 하나로는 아무리 성형해도 "삑"이지 "또로롱"이 아니다.

- **판 클리어**: 저음(C3) + 종 4음(C5·E5·G5·**C6**) + 음정 없는 반짝임. 총 1279ms.
  옥타브로 닫는 게 중요하다 — 5도로 끝내면 "아직 안 끝났다"로 들린다.
- **연쇄**: 유리 샘플 위에 종의 배음을 얹는다. 기본음 300 → 450Hz 반음씩 상승 (실측).
- **해금**: 딸깍(샘플) 위에 두 음. 딸깍만으로는 방향이 없어 그냥 버튼 소리였다.
- 버그 하나 같이 고쳤다: `echoScale` 의 `lastAt` 이 0으로 열려 있어
  **각 종류의 첫 소리가 통째로 버려지고 있었다** (AudioContext는 currentTime 0 근처에서 태어난다).

`npm run probe` 가 예약 시각·음정·게인을 표로 찍는다 (`tools/probe-audio.ts`).

## 5. 화면

### 월드 (`src/render/scene.ts`)
- **과녁**: 얇은 원 두 개 → 면으로 채운 띠 넷 (밝은 테 / 어두운 띠 / 강조 / 흰 중심).
  어두운 배경에서 작은 과녁이 묻히던 문제와 "중심이 어디인가" 둘 다 해결. 색은 안 늘렸다.
- **종류가 모양으로 읽힌다**: 관통 = 마름모, 이동 = 왕복 레일, 낮은 과녁 = 지면 기둥,
  공중 = 후광 + 매단 줄.
- ★ **바람 깃발.** 26판부터 바람이 부는데 화면에 바람이 **하나도 없었다**.
  GDD가 적어둔 "깃발을 보고 기다렸다 쏜다"가 성립할 수가 없었다.
  풍속 2 m/s에서 -44°, 4에서 -16°, 5 이상 수평 (렌더 프로브 실측).
- 화살에 촉과 깃 / 하늘에 달·별 / 지면에 풀 / **빗나간 화살이 땅에 박혀 남는다**
  (다섯 발이 과녁 아래 나란히 박혀 있으면 조준이 아니라 낙차를 못 읽고 있다는 게 보인다).
- 한 프레임 draw 호출 125회.

### HUD (`src/render/hud.ts`)
- ★ **판 번호와 판 이름이 지금까지 화면 어디에도 없었다.** 머리글 + 판 시작 자막(1.6초).
- 전부 창 크기에 비례. 1280×800 기준 화살 수 30 → **46px**, 과녁 16 → 23px. 1920에서 62px.
- 글꼴에 역할을 줬다 — 한글 스택 / DIN 계열 숫자 스택.
- 바람 방향·세기 눈금 (오른쪽 위).

### DOM 패널 (`src/ui/`)
- 본문 13 → 15px, 패널 520 → 680px, 드래프트 카드 132 → 190px.
- 모서리 6px 라운드 → 2~3px. 강조는 **한 곳에만** — 패널 위 3px 띠, hover의 왼쪽 잉크 바.
- 디자인 토큰(`--ink`, `--line` …)과 공통 클래스(`.hb-sec`, `.hb-lead`)를 overlay가 한 곳에서 정의.
