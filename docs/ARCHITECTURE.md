# 기술 정관 (Architecture Constitution)

이 문서의 규칙을 어기는 코드는 리뷰에서 반려된다.

---

## A1. 결정론 (Determinism) — 가장 중요한 규칙

**같은 시드 + 같은 입력 = 항상 같은 결과.**

이유는 재미가 아니라 **개발 속도**다. 결정론이 있으면:
- 헤드리스로 1만 판을 돌려 밸런스를 수치로 검증할 수 있다
- 버그 리포트를 리플레이 하나로 100% 재현할 수 있다
- AI 에이전트가 "느낌"이 아니라 **숫자**로 튜닝 결과를 판정할 수 있다

### 지켜야 할 것

```
sim/ 아래 코드는 다음을 절대 참조하지 않는다:
  ✗ Math.random()        → core/rng.ts 의 시드 RNG만 사용
  ✗ Date.now()           → 시뮬레이션 내부 시계(tick)만 사용
  ✗ performance.now()
  ✗ window / document / canvas
  ✗ 프레임 delta 시간     → 고정 스텝만
```

- **고정 스텝 120Hz.** 렌더는 남은 시간만큼 보간(interpolate)한다.
- 렌더 프레임이 30fps든 144fps든 시뮬 결과는 비트 단위로 동일해야 한다.
- 부동소수점 누적 오차를 줄이려 각도는 라디안, 위치는 미터(m) 단위로 통일.

### 레이어 의존 방향 (단방향)

```
  core  ←  sim  ←  game  ←  render / input / ui
   ↑                            ↑
   └────────── tune ────────────┘

  core   : 순수 유틸 (rng, vec2, 수학). 의존 없음.
  sim    : 물리·활·화살·과녁. DOM 모름. 테스트 가능.
  game   : 스테이지·진행·성장·저장·오프라인. sim을 구동.
  render : Canvas2D. game 상태를 읽기만 한다. 절대 쓰지 않는다.
  input  : 입력을 sim 이벤트로 변환. 직접 상태를 건드리지 않는다.
  tune   : 모든 조율 상수의 단일 출처. 어느 레이어든 읽는다.
```

**render가 sim 상태를 변경하면 결정론이 깨진다.** 이건 리뷰 자동 반려 사유다.

## A2. 튜닝 상수의 단일 출처

손맛에 관여하는 모든 숫자는 `src/tune/params.ts` **한 파일**에만 존재한다.

```ts
// ✗ 나쁨 — 코드 곳곳에 마법의 숫자
if (holdTime > 2.4) tremor *= 1.8

// ✓ 좋음
if (holdTime > P.bow.tremorRampStart) tremor *= P.bow.tremorRampMul
```

이유: 라이브 튜닝 콘솔(`src/tune/console.ts`)이 이 객체 하나만 조작하면 게임 전체 손맛이 바뀐다.
튜닝 세션 후 콘솔에서 JSON을 export → `params.ts`에 붙여넣기 → 커밋. 이게 이 프로젝트의 디자인 워크플로다.

## A3. 탭 생명주기 (C1·C3 직결)

```
visibilitychange → hidden  : sim 정지, rAF 취소, 오디오 정지, 즉시 저장
visibilitychange → visible : 저장된 wallclock과 비교해 오프라인 축적 정산 → 복귀 화면
```

- 백그라운드 탭에서 **절대 rAF/setInterval을 돌리지 않는다.** 공부 중 CPU를 먹으면 안 된다. (C3)
- 오프라인 축적은 시간 경과 **계산**으로 처리한다. 시뮬레이션을 몰아 돌리지 않는다.
- 저장은 `visibilitychange`, `pagehide`, 판 종료 시점. 주기적 저장 타이머 금지.

## A4. 저장 (Save)

- `localStorage` 단일 키 (`hanbal.save.v1`). JSON.
- **스키마 버전 필드 필수.** 마이그레이션 함수 체인으로 올린다. 세이브를 깨뜨리지 않는다.
- 저장 실패(용량 초과/프라이빗 모드)해도 게임은 계속 돌아가야 한다. try/catch 필수.
- 치트 방지 안 한다. 싱글플레이 개인 게임이다.

## A5. 성능 예산

| 항목 | 예산 | 초과 시 |
|------|------|---------|
| 번들 (gzip) | < 60KB | 라이브러리 추가를 의심 |
| 첫 페인트 | < 300ms | 초기화 코드 분할 |
| 프레임 예산 | 16.6ms 중 sim 2ms / render 6ms | 프로파일 |
| 프레임당 힙 할당 | 0 (핫 루프) | 객체 풀링 |

- 핫 루프에서 `{}`, `[]`, 클로저 생성 금지. 벡터는 값 두 개(x, y)를 그대로 넘기거나 풀에서 꺼낸다.
- 파티클은 고정 크기 링버퍼.

### A5-1. 그래픽 단계 (삼한열전 앱 · 2026-10-29)

**왜:** 10-29 형의 폰에서 앱 그림이 갑자기 다 깨졌다. 폰의 절전 · 초절전 모드가 세져서 웹이 그려야 할 것을 못 그린 것이다.
절전 모드의 크롬은 프레임을 30장으로 묶고 그래픽 칩을 덜 쓰는데, 그 상태에서 `filter`(drop-shadow · blur · 밝기) ·
`mix-blend-mode` · `backdrop-filter` · 끝없이 도는 꾸밈 움직임이 겹치면 층이 한도를 넘어 그림이 빠지거나 깨진다.
배터리도 많이 먹었다. 그래서 단계를 나눴다 (`src/ui/realm/quality.ts` · 앱 뿌리 `.ap.q-low / .q-mid / .q-high` · JS 는 `quality()`).

| 단계 | 끄는 것 |
|------|---------|
| 고사양 | 없음 (지금 그대로) |
| 보통 | 화면 섞기 · 뒤 흐림 · filter 의 blur · 두 겹 넘는 drop-shadow · 입자 반 |
| 저사양 | filter 전부(어둡게 · 잿빛은 opacity 로 남김) · 화면 섞기 · 뒤 흐림 · will-change · 큰 그림자 얕게 · 끝없는 꾸밈 움직임 멈춤(한 장으로) · 입자 넷에 하나 · 계절 입자 없음 |

- **끝없는 움직임만 멈추는 법:** 켤 때 스타일시트를 한 번 읽어, 움직임을 단 규칙마다 `:where(.ap.q-low) :is(원래 선택자) { animation-play-state: … }`
  쌍둥이를 만든다. `:where` 라 세기가 원래와 같아 덮는 차례가 그대로다. 공격 · 맞음 · 숫자 · 판정처럼 한 번 도는 것은 그대로 돈다.
- **자동:** 폰은 보통 · 마우스 컴퓨터는 고사양에서 시작. 첫 지도 · 첫 싸움 · 탭 복귀 때 2초 프레임을 재서 가운데값 28ms 초과(절전의 30장)나
  긴 프레임이 많으면 한 단계 내린다. 배터리 20% 아래(충전 아님)도 내림. 메모리 4GB 이하는 보통까지. 자동은 **내리기만**, 1분에 한 번까지.
  저사양이 되면 한 줄 알림. 손으로는 더 보기 · 나라 탭의 「그래픽」(`hanbal.realm.gfx`), 시험은 주소 `?gfx=low`.
- **가만히 둔 때(모든 단계):** 45초 아무것도 안 누르면 꾸밈 움직임을 멈춘다 (`.q-rest` · 싸움 중엔 안 멈춤). 누르면 바로 돈다.
- 새 꾸밈을 넣을 때: 끝없는 움직임 · filter 는 쌍둥이가 알아서 단계를 탄다. **입자를 여럿 뿌리면** quality.ts 의 `SPARKS` · `PIECES` 에 그 선택자를 더한다.
- 숫자(재는 시간 · 문턱 · 쉬기까지)는 `P.realm.gfx*`.

## A6. 의존성 정책

**런타임 의존성 0개를 기본으로 한다.** 추가하려면 아래를 문서로 답해야 한다:
1. 직접 짜면 몇 줄인가?
2. 번들이 몇 KB 늘어나는가?
3. 결정론을 해치지 않는가?

## A7. 테스트

- `tests/` : `node --test`. sim 레이어의 결정론·물리 불변식 검증.
- **불변식(invariant) 테스트를 우선한다.** 예: "화살 에너지는 발사 후 절대 증가하지 않는다", "같은 시드로 두 번 돌리면 최종 상태가 동일하다".
- `tools/balance-sim.ts` : 봇이 N판 자동 플레이 → 승률·평균 점수·성장 곡선 CSV 출력.
  밸런스 판단은 감이 아니라 이 출력으로 한다.

## A8. 파일·명명 규칙

- 파일명 kebab-case, 타입 PascalCase, 함수/변수 camelCase, 튜닝 상수는 `P.<영역>.<이름>`
- 한 파일 400줄 넘으면 분리를 검토
- 주석은 **"왜"**만 쓴다. "무엇"은 코드가 말한다.
- 게임 용어는 GDD 표기를 따른다 (만작, 붕괴, 호흡정지, 연쇄, 훈련치)
