# 밸런스 검증

**감으로 판단하지 않는다.** 봇에게 만 판을 시키고 통계를 본다.

## 절차

### 1. 시뮬을 돌린다
```bash
npm run balance
```
`tools/balance-sim.ts` 가 시드 고정 봇으로 스테이지를 자동 플레이하고 CSV/표를 낸다.

봇은 실력 수준별로 여러 명이어야 한다:
- `novice` — 떨림 위상을 못 읽음, 릴리즈 타이밍 랜덤
- `average` — 위상을 절반쯤 읽음
- `expert` — 위상 최저점 근처에서 릴리즈

한 명만 있으면 "누구에게 적당한가"를 알 수 없다.

### 2. 목표 수치와 비교

| 지표 | 목표 | 위험 신호 |
|---|---|---|
| 챕터별 average 봇 첫시도 클리어율 | 55~75% | >95% (지루) / <20% (벽) |
| 새 메커닉 챕터의 클리어율 하락 | ≤ 25%p | 그 이상이면 학습 곡선 급경사 |
| novice~expert 클리어율 격차 | 30~50%p | 너무 작으면 실력이 개입 안 함 |
| 25분 공부 후 플레이 가능 판 수 | ≥ 3판 | 미만이면 자원이 병목 |
| 스탯 1포인트의 후반 효과 | ≥ 초반의 20% | 미만이면 성장이 죽음 |

### 3. 원인을 지목한다

클리어율이 낮으면 **왜** 낮은지 시뮬 출력에서 찾는다:
- 붕괴로 끝난 비율이 높다 → `stamina` 계열
- 명중했는데 점수가 모자란다 → 스테이지 목표치
- 화살이 목표에 못 닿는다 → `bow.maxSpeed` 또는 거리 설계

증상이 아니라 원인을 고친다.
