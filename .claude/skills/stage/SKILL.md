# 스테이지 저작

## 설계 원칙

### 1. 한 판은 30초~1분, 화살 5~8발
넘어가면 GDD 제약 C1 위반이다. 공부 사이에 들어갈 수 없다.

### 2. 한 판에 배울 것은 하나
새 메커니즘을 두 개 동시에 도입하지 않는다. 챕터 6(연쇄)에서 바람도 같이 세게 불면 아무것도 안 배운다.

### 3. 첫 발이 안내가 되게
판이 시작됐을 때 **말 없이 무엇을 해야 할지 보여야 한다.** 텍스트 튜토리얼을 쓰지 않는다.
- 배치로 가르친다: 연쇄를 가르치려면 첫 과녁 바로 아래에 두 개를 나란히 둔다
- 실패해도 왜 실패했는지 궤적으로 읽히게 (`hit.missTrailFade`)

### 4. 챕터 구조 (GDD 6장)
챕터 = 10판. 구조:
- 1~2판: 새 메커닉을 안전한 환경에서 소개
- 3~7판: 변주
- 8~9판: 이전 챕터 요소와 조합
- 10판: 종합 시험

### 5. 무한 모드
절차 생성이면 **시드에서 완전히 결정**되어야 한다 (ARCHITECTURE A1).
난이도 파라미터를 스테이지 번호의 함수로 정의하고, `tools/balance-sim.ts` 로 1~500스테이지를 훑어 곡선을 확인한다.

## 절차

1. 어떤 판인지 한 문장으로 쓴다 — "바람이 오른쪽으로 강할 때 리드샷을 배우는 판"
2. 스테이지 데이터를 작성한다 (좌표·과녁 종류·바람·화살 수·목표)
3. `npm run balance` 로 봇 클리어율 확인 — 목표 55~75%
4. `/playtest` 로 실제로 쏴본다
5. `balance-lens` 통과

## 하지 말 것
- 운으로 결정되는 판 (돌풍이 랜덤으로 판을 결정하면 안 된다 — 읽을 수 있어야 한다)
- 화살이 모자라 재시도를 강제하는 판 (C2 위반)
- 1분을 넘기는 판
