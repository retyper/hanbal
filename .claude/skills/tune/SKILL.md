# 손맛 튜닝

이 게임에서 가장 어려운 작업이다. 코드를 고치는 게 아니라 **숫자를 찾는 일**이다.

## 철칙

1. **`src/tune/params.ts` 밖의 숫자는 건드리지 않는다.** 손맛 상수가 다른 데 있으면 그건 A2 위반이니 먼저 params.ts로 옮긴다.
2. **한 번에 하나씩 바꾼다.** 세 개를 동시에 바꾸면 무엇이 효과를 냈는지 영원히 모른다.
3. **바꾸기 전에 무엇이 문제인지 한 문장으로 쓴다.** "뭔가 이상하다"로는 튜닝할 수 없다.

## 절차

### 1. 증상을 물리량으로 번역한다

형이 말한 감각을 SPEC의 어느 노브가 지배하는지 찾는다.

| 형이 하는 말 | 볼 노브 |
|---|---|
| "당기는 게 뻑뻑해 / 느려" | `bow.drawTime`, `growth.strToDrawTime` |
| "떨림이 안 보여" | `tremor.baseAmp`, `tremor.minVisiblePx` (화면 스케일 확인) |
| "떨림이 너무 규칙적이야" | `tremor.fastRatio`, `tremor.slowFreq`/`fastFreq` 비율 |
| "언제 놓아야 할지 모르겠어" | 떨림 위상 가독성 — `fastRatio` 낮추고 `slowFreq` 낮춰 느린 스윙을 키운다 |
| "갑자기 놓아버려서 억울해" | `stamina.collapseWarnAt`, `collapseWarnMinTime` |
| "명중이 밍밍해" | `hit.stopMs`, `hit.shakeAmp` |
| "화면이 정신없어" | `hit.shakeAmp` 낮추고 `chain.maxParticles` 줄인다 |
| "왜 빗나갔는지 모르겠어" | `hit.missTrailFade` 올려서 궤적을 더 오래 남긴다 |
| "화살이 너무 빨라 / 느려" | `bow.maxSpeed`, `arrow.drag` |

### 2. 라이브 콘솔로 먼저 찾는다

코드를 고치기 전에 게임을 띄우고 ` 키로 콘솔을 열어 슬라이더로 값을 찾는다.
(`/playtest` 참조. 브라우저 도구의 `javascript_tool` 로 `setParam('tremor.baseAmp', 0.006)` 을 직접 호출해도 된다.)

**세 개의 후보값을 만든다** — 확실히 약함 / 후보 / 확실히 강함. 세 개를 비교해야 방향이 잡힌다.

### 3. params.ts에 반영하고 근거를 남긴다

`k(...)` 의 첫 인자를 바꾸고, **왜 이 값인지 주석으로 남긴다.**

```ts
// 0.0042 -> 0.0055: 1080p에서 조준점 진폭이 1.8px라 위상이 안 읽혔다 (feel-lens 지적)
baseAmp: k(0.0055, 0, 0.03, 0.0002, '기본 떨림 진폭', 'rad'),
```

주석 없는 튜닝 변경은 6주 뒤에 되돌려진다. 반드시 남긴다.

### 4. 검증

```bash
npm test        # 결정론이 안 깨졌는지
npm run balance # 난이도가 뒤집히지 않았는지
```

떨림/속도를 건드리면 밸런스가 통째로 움직인다. `balance-lens` 를 함께 돌린다.

### 5. 렌즈 통과

`feel-lens` 에이전트를 돌려 손맛 판정을 받는다. 지적이 나오면 다시 2번으로.
